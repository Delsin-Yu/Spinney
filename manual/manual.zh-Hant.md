# Spinney 使用手冊

Spinney 是 VS Code 擴充功能。它把代理放進編輯器分頁，並把對話保存成可分支的樹。

Version: 0.0.2.

## 1. 安裝與首次執行

1. 從 Visual Studio Marketplace 安裝 **Spinney**。
2. 在活動列中開啟 **Spinney** 容器。它包含 **工作階段** 檢視。
3. 在檢視標題列中點選 **Spinney: 新增工作階段**。接著開啟一個分頁，標題是 `代理聊天樹 — 新增工作階段`。
4. 設定 API 金鑰（第 2 節）。然後在下方的方塊中寫下你的第一則訊息，並按 **Enter**。

`Shift+Enter` 會換行。`Enter` 會傳送。

資料夾已開啟或未開啟時，Spinney 都能運作。請參閱第 16 節。

全新的設定檔會使用內建模型卡片 `deepseek-flash`。你可以變更它（第 6 節）。

## 2. 設定 API 金鑰

Spinney 把金鑰保存在 VS Code 密鑰儲存區，絕不寫入 `settings.json`。

1. 用 `Ctrl+Shift+P` 開啟命令選擇區。
2. 執行 **`Spinney: 設定 API 金鑰`**。
3. 在提示中貼上金鑰並確認。

VS Code 會以 `Spinney：API 金鑰已儲存。` 確認。金鑰立即生效。你不需要重新載入視窗。

執行 **`Spinney: 清除 API 金鑰`** 可清除金鑰。

兩項特殊規則：

- 內建供應商也接受 `DEEPSEEK_API_KEY` 環境變數。只有在沒有已儲存的金鑰時，Spinney 才會使用該變數。
- 供應商多於一個時，請在模型卡片頁面（第 6 節）中該供應商的那一列設定每個金鑰。

沒有金鑰時，每個要求都會失敗，並顯示 `No API key configured for this provider.`。Spinney 每個視窗顯示一次 `設定 API 金鑰` 按鈕。

## 3. 聊天視窗

樹中每個回合有一個卡片。新的回合會放在它所回答的回合下方。輸入區是輸入用的停駐區。它位於你簽出的卡片內。

### 3.1 輸入區

| 控制項 | 功能 |
|---|---|
| 輸入方塊 | 存放你的訊息。`Enter` 傳送，`Shift+Enter` 換行。 |
| **傳送** | 傳送訊息並開始一個回合。設定變更時，Spinney 會標記這個按鈕（第 3.4 節）。 |
| **停止** | 結束簽出節點上的回合。它也會終止該節點的背景終端和子代理。不會有任何東西繼續。工具提示是 `停止這一輪`，或 `停止這個節點：終止它的背景工作與子代理（不會傳送任何內容給模型）`。 |
| 提示詞片段 | 開啟預先寫好的指示選單。點選一次會把文字插入輸入方塊。不會傳送任何內容。Spinney 內建 `Plan` 和 `Implement Parallel`。用 `spinney.promptSections` 新增你自己的項目（第 11 節）。 |
| **附加圖片** | 開啟檔案選擇器。你也可以把圖片貼到輸入方塊中。請參閱第 9 節。 |
| 模型下拉式選單 | 挑選新節點要用的模型卡片。繼續這段對話的傳送會先詢問（第 3.4 節）。清單會依供應商分組。 |
| 齒輪按鈕 | 開啟模型卡片頁面。工具提示是 `管理模型卡片…`。 |
| 推理力度下拉式選單 | 挑選思考層級。清單就是作用中卡片的清單。 |

**傳送** 和 **停止** 是同一個按鈕的兩種含義。當簽出節點正在執行回合，或該節點仍擁有未完成的工作時，按鈕會顯示 **停止**。

當背景終端或子代理批次正在執行，或有完成通知在等該節點時，該節點就擁有未完成的工作。你無法傳送到這樣的節點。這裡沒有佇列。請先按 **停止**，或從另一個節點傳送。

另一條分支或另一個工作階段可以同時執行。它不會封鎖這個輸入區。

子代理卡片沒有輸入區。它的分支是唯讀的，橫幅會顯示 `子代理分支（唯讀）— 由主代理透過 spawn_agents / send_agent_message 驅動`。

### 3.2 樹狀工具列與手勢

工具列有兩個按鈕：

- **跟隨作用中節點**（`⦿`）。檢視會讓正在串流的節點留在畫面上。
- **調整為符合檢視**（`⤢`）。

| 手勢 | 結果 |
|---|---|
| 滾輪 | 捲動檢視。 |
| `Ctrl`+滾輪 | 縮放。 |
| `Shift`+滾輪 | 水平平移。 |
| 按住滑鼠中鍵拖曳 | 平移。 |
| 按住滑鼠右鍵 | 朝指標方向平移。 |
| 拖曳卡片的右下角 | 調整該卡片的大小。 |
| 在卡片標頭按滑鼠右鍵 | 開啟卡片選單。其中有 `複製節點 ID`。 |

手動平移或縮放會關閉該按鈕。

每個卡片標頭都有回合標題、狀態標籤，以及一個 **🗑** 按鈕。該按鈕會刪除該回合所在的分支（第 4 節）。

卡片主體由上到下有三個部分。

第一部分包含你的訊息。Spinney 一律顯示這個部分，絕不摺疊它。Spinney 以 Markdown 呈現這個部分。

第二部分是工作日誌。它包含推理區塊、工具卡片、通知、背景工作通知、`HARNESS` 區塊，以及模型在工具呼叫之前寫下的文字。工作日誌會捲動。只有它帶有綠色鎖定圓點。圓點控制自動捲動。進行中的回合一開始是鎖定的。當回合完成時，工作日誌會自動摺疊成一個單行標頭。該標頭帶有一個箭頭和一個標籤。標籤顯示為 `工作日誌 · 3 個步驟`。該數字是工具卡片的數量。沒有工具卡片時，標籤只顯示 `工作日誌`。點選該標頭可再次展開工作日誌。你點選過一次的標頭會保持你留下的狀態。自動摺疊絕不會推翻你的點選。鎖定圓點遵循同樣的規則。當你鬆開某張卡片的鎖定圓點時，自動摺疊不再摺疊或展開這張卡片的工作日誌。回合再次執行時，工作日誌會自動展開。卡片沒有回答可顯示時，工作日誌保持展開。把 `spinney.foldWork` 設為 `false` 可關閉自動摺疊（第 11 節）。工作日誌中的區塊保留各自的摺疊行為（請見下方，以及第 11 節的 `spinney.foldThinking` 和 `spinney.foldToolCalls`）。

第三部分是回答。它包含模型的最終訊息。Spinney 把它顯示在卡片底部，以 Markdown 呈現它，且絕不摺疊它。回答不帶鎖定圓點。只有在回合靜止，且工作日誌的最後一項是模型的訊息時，Spinney 才顯示回答。工作日誌出現較新的項目時，回答就會消失，例如背景工作、回報結果的子代理、來自 **▶ 繼續** 或 **↻ 重試** 的 `HARNESS` 區塊，或新的工具呼叫。此時那則訊息又回到工作日誌中。已中斷回合的文字會顯示為回答。發生錯誤回合的文字不會顯示為回答。錯誤會留在工作日誌中。

當卡片顯示回答，且工作日誌保持展開時，回答優先，且只有回答的高度會使卡片變高。工作日誌保留約 360 像素的條帶，並在這條條帶內捲動。拖曳卡片的右下角可以讓這條條帶更高。回合執行期間還沒有回答，卡片保持同樣的條帶高度，不會隨著每次工具呼叫而變高。回答位於分隔線下方、屬於它自己的表面上。

卡片現在最高可達 1200 像素。舊上限是 600 像素。拖曳卡片的右下角仍可調整它的大小。

按 `Ctrl+Alt+D` 可把版面診斷寫入輸出通道。

### 3.3 狀態列

輸入方塊下方的列顯示工作階段的狀態。

| 項目 | 含義 |
|---|---|
| 狀態圓點 | 工作階段閒置時變暗。有任何內容在串流時呈琥珀色並閃爍。 |
| 狀態列文字 | `就緒`、`思考中…`、`正在上傳圖片…`、`正在停止…`、`已中斷`、`錯誤`，或重試訊息（第 10 節）。 |
| `ctx N%` | 內容視窗用量。它把**上一次**要求的提示 token 除以卡片的 `contextWindow`。這是讀數，不是限制。它可能不正確。 |
| `bal …` | 作答供應商的餘額。`bal –` 表示沒有數字，例如餘額讀取方式為 `none` 的供應商。Spinney 只讀取餘額一次，絕不重試。 |
| `tok/s` | 輸出速度。這是本機估算值，不是供應商的計數。 |

每個回答和每個工具卡片都有自己的 token 列：`tokens {0}（提示 {1} + 補全 {2}）· 快取命中 {3} / 未命中 {4}`。

工具卡片包含呼叫、參數和結果。每個工具卡片都會顯示這次呼叫的耗時，呼叫結束後該數字仍會保留。`HARNESS` 區塊包含 harness 傳送給模型的確切文字。推理區塊、工具卡片和 `HARNESS` 區塊都位於工作日誌中。點選區塊標頭可摺疊或展開它。`spinney.foldThinking` 和 `spinney.foldToolCalls` 設定這些區塊的預設摺疊狀態（第 11 節）。

刻意保持英文的代碼：`SUB`、`BG`、`CTX`、`HARNESS`、`Delivered`。

### 3.4 凍結的設定與多棵樹

對話凍結在它開始時使用的設定上。該設定包含模型卡片、思考層級、回覆語言，以及隨擴充功能發布的系統提示。一次普通的傳送一律使用該凍結的設定。

挑選另一張模型卡片、另一個思考層級或另一種回覆語言，會讓即時設定與凍結的設定不同。此時輸入區會同時顯示這兩種設定，各佔一行：

- `Sending with: {0}`。一次傳送真正使用的設定。
- `New setup: {0}`。新節點將凍結的設定。

其中的值包含卡片、思考層級和回覆語言。例如：`Sending with: deepseek-flash · medium · English`。

設定變更之前，Spinney 只問一個問題。問題是 `Continue with current setup` 或 `Continue with latest setup`。它出現在三種情況下：

- 變更模型下拉式選單、推理力度下拉式選單或 `spinney.replyLanguage`（第 11 節）。Spinney 會標記 **傳送** 按鈕。工具提示是 `Send will ask before using the old setup (the one this node froze)`。
- harness 端發生變化：隨擴充功能發布的系統提示、工作區 `AGENTS.md`、工具集或端點。Spinney 會在提示詞片段旁新增一個提示項。該項帶有 `⧉` 符號，工具提示是 `Continue with the latest setup (forks this tree and sends there)`。點選它會開啟同一個問題。
- 在新的內容視窗中繼續（第 10.3 節）。空白內容讓最新設定不付出代價，所以那裡也會問一次。

| 回答 | 會發生什麼 |
|---|---|
| `Continue with current setup` | 傳送使用凍結的設定。Spinney 會捨棄你的選擇。模型下拉式選單和推理力度下拉式選單會重新顯示凍結的值。 |
| `Continue with latest setup` | Spinney 把這棵樹複製成一棵新樹。新樹以最新設定開始。舊樹保留它自己的設定，以及它的提示快取。 |

按 `Escape`，或點選關閉按鈕，即可關閉這個問題。被關閉的問題不會傳送任何內容，Spinney 會把你輸入的文字留在輸入方塊中。

一個工作階段可以容納多棵樹。Spinney 把新樹放在目前這棵樹旁邊。檢視會並排顯示這些樹，並把檢視移到新樹，每棵樹都可以互動。簽出你想繼續的那棵樹中的節點，然後傳送。

### 3.5 重新載入聊天檢視

聊天分頁可能顯示對話的舊畫面。例如某個卡片不再變化，或只顯示樹的一部分。對話是正確的，正在執行的回合也會繼續。

執行 **`Spinney: 重新載入聊天檢視`**，從工作階段的狀態重新建立該分頁。當分頁顯示凍結的畫面，或某個卡片不再變更時，使用此命令。

此命令不會變更對話。它不會停止正在執行的回合。沒有開啟的聊天分頁時，Spinney 會回答 `Spinney：此視窗沒有開啟的聊天分頁。`

## 4. 分支

### 4.1 從回合分支

1. 點選你想從中分支的回合標頭。卡片會展開，輸入區會移入其中。
2. 寫下新訊息。當該回合已有子節點時，橫幅會顯示 `⤷ 從 {0} 分支 — 你的回覆會開啟新分支`。
3. 按 **Enter** 或點選 **傳送**。

新的回合會成為同層分支。Spinney 不刪除任何內容。舊的路徑會以變暗的單列卡片留在樹中。點一下就能讓它回來。

簽出不受限制。你可以在某個回合串流時簽出另一個回合。簽出只移動檢視，不移動正在執行的回合。

### 4.2 刪除分支

1. 把滑鼠移到該分支起始回合的標頭上方。
2. 點選 **🗑**。工具提示是 `刪除此分支 — 本回合及其以下的所有內容`。
3. 閱讀確認內容。它會列出回合數、將消失的逐字稿傾印，以及 Spinney 會終止的背景終端。點選 **刪除分支**。

命令選擇區命令 `Spinney: 刪除簽出回合處的分支` 對簽出回合做同樣的事。

Spinney 會在兩種情況下拒絕刪除：

- 工作階段中有回合正在執行：`代理執行期間無法刪除分支。請等該回合結束。`
- 分支內有子代理正在執行：`無法刪除包含正在執行的子代理的分支。請先終止它。`

刪除之後，簽出會移到該分支的父節點。刪除是永久性的。逐字稿傾印也會離開磁碟，因此 `search_transcripts` 再也找不到它們。

### 4.3 停止

**停止** 是一個動作、一種含義：停止該節點擁有的一切。

| 正在執行的內容 | 停止會做什麼 |
|---|---|
| 該節點的回合 | 中止它。部分輸出會留在卡片中。 |
| 它的子代理 | 終止整個批次及其深度 2 的子項。 |
| 它的背景終端 | 終止處理程序樹。 |
| 已排隊的完成通知 | 改為把通知寫入該節點的歷史。模型會在你下一次提示時，或在你按 **▶ 繼續** 時看到它。 |

停止只影響一個節點。其他分支和其他工作階段會繼續執行。

## 5. 工作階段與分頁

**工作階段** 檢視會列出每個工作階段，最近變更的排在最前面。每一列顯示標題、狀態圖示，以及一行 `{0} node(s) · <time>`。正在執行回合或背景工作的工作階段會顯示旋轉圖示。

一個工作階段只擁有一個分頁。開啟工作階段會聚焦它的分頁。它絕不會開啟第二個分頁。

| 動作 | 做法 |
|---|---|
| 新增工作階段 | 在檢視標題列中點選 **Spinney: 新增工作階段**。 |
| 開啟工作階段 | 在清單中點選它的那一列。 |
| 重新命名 | 在該列按滑鼠右鍵，然後選 `Spinney: 重新命名工作階段…`。手動重新命名會鎖定標題。 |
| 自動重新命名 | 在該列按滑鼠右鍵，然後選 `Spinney: 自動重新命名工作階段`。這會解除鎖定，並立即重新產生標題。 |
| 複製工作階段 id | 在該列按滑鼠右鍵，然後選 `Spinney: 複製工作階段 ID`。 |
| 刪除一個工作階段 | 把滑鼠移到該列上方，然後點選 **🗑**。 |
| 刪除多個工作階段 | 按住 `Ctrl` 或 `Shift` 點選這些列，然後在任何已選取的列上點選 **🗑**。Spinney 會在一個確認之後刪除整個選取範圍。 |
| 清除對話 | 執行 `Spinney: 清除對話`。 |

開啟 `spinney.autoSessionTitles` 後，Spinney 會在第一次回合之後依對話為工作階段命名，並在對話增長時再次命名。兩次命名之間至少間隔兩分鐘。手動重新命名會停止自動命名。

工作階段歷史存放在擴充功能的工作階段資料資料夾中，是一般檔案：每個工作階段一個資料夾，每個節點一個檔案。

| 操作 | 結果 |
|---|---|
| 匯出資料 | `Spinney: 匯出工作階段資料` 把該資料夾複製到你指定的位置。已刪除的工作階段與內部鎖不會一併匯出。 |
| 匯入資料 | `Spinney: 匯入工作階段資料` 把另一個資料夾中的工作階段併入目前視窗。已存在的工作階段不會被取代。 |
| 把資料放在同步磁碟 | 把 `spinney.dataDir` 設為該資料夾。下次重新載入視窗後生效。 |

| 事件 | 會發生什麼 |
|---|---|
| 重新載入視窗，或重新啟動 VS Code | 工作階段和已開啟的分頁會回來。 |
| 關閉分頁 | 工作階段會保留。只有分頁消失。正在執行的回合會繼續。 |
| 第二個視窗開啟同一個資料夾 | 一個資料夾的工作階段由一個視窗擁有。另一個視窗顯示相同的工作階段，你可以在那裡瀏覽和閱讀它們。它拒絕每一次變更：傳送、繼續、新增工作階段、刪除、重新命名和清除。訊息是 `Another window owns this workspace’s sessions, so this window is read-only. Close that window (or use it) to continue here.` |
| 刪除工作階段 | Spinney 移除歷史、刪除逐字稿傾印，並終止背景終端。有回合在執行時，它會拒絕。 |
| 刪除最後一個工作階段 | Spinney 建立一個全新的空白工作階段。 |
| 換一台電腦 | 在舊機執行 `Spinney: 匯出工作階段資料`，在新機執行 `Spinney: 匯入工作階段資料`。 |

## 6. 模型與供應商

**模型卡片** 是一個可選取的模型。**供應商** 是一個端點。一張卡片永遠只指定一個供應商。

用 **`Spinney: 開啟模型卡片`** 開啟模型卡片頁面，或用聊天模型下拉式選單旁的齒輪按鈕。頁面把供應商畫成根、把卡片畫成分支。選取一個節點即可開啟它的表單。

頁面把你的編輯保留為草稿。它會在分頁標題顯示 `* `，並在狀態列顯示 `有未儲存的修改。`。**儲存** 會一次寫入所有內容。**還原** 會捨棄草稿。

Spinney 會在頁面中檢查草稿，並在主機中再檢查一次。被拒絕的儲存不會寫入任何內容。

頁面儲存在 `settings.json` 的 **Global** 範圍，因此這些卡片屬於你的 VS Code 設定檔。其他每個 `spinney.*` 設定鍵都以視窗為範圍。

### 6.1 供應商欄位

| 欄位 | 含義 |
|---|---|
| id | `spinney.providers` 中的設定鍵。它永遠不會變。id 為 `default` 的一列會取代內建供應商。 |
| `name` | 顯示名稱。Spinney 會在模型下拉式選單的分組、餘額列和 API 金鑰提示中顯示它。 |
| `baseUrl` | API 根網址，例如 `https://api.deepseek.com`。要求會送到 `POST <baseUrl>/chat/completions`。 |
| `balance` | Spinney 讀取剩餘額度的方式。請參閱下表。 |
| `concurrency` | 同時可以對這個端點發出多少個要求。`0` 表示不限。 |

| `balance` 值 | 要求 | 結果 |
|---|---|---|
| `none` | 不發出要求。 | 沒有餘額數字。這是新一列的預設值。 |
| `deepseek` | `GET /user/balance` | 總額、贈送部分和加值部分。 |
| `openrouter` | `GET /credits` | 剩餘額度，以 USD 計。 |
| `moonshot` | `GET /users/me/balance` | 可用餘額，以 CNY 計。 |

沒有填 `balance` 的一列會依它的主機來讀取：`api.deepseek.com` 得到 `deepseek`，其他則得到 `none`。

### 6.2 模型卡片欄位

| 欄位 | 含義 |
|---|---|
| id | 自動產生的 id。它永遠不會變，因此重新命名是安全的。工作階段和逐字稿儲存的是 id。 |
| `name` | 模型下拉式選單中的標籤。兩張卡片不能共用名稱。 |
| `providerId` | 此卡片對話的供應商。 |
| `oaiModel` | 放進要求的傳輸模型名稱。新卡片在你設定它之前無效。 |
| `contextWindow` | 卡片的 token 預算。`ctx` 讀數會除以它。它不是 API 的輸出上限。 |
| `concurrency` | 此卡片可以同時發出多少個要求。`0` 表示不限。卡片絕不會超過其供應商的上限。 |
| `vision.enabled` | 卡片是否接受影像。 |
| `vision.transport` | `deepseek` 把影像上傳到 `POST /files`，並引用傳回的 id。`openai` 把 `data:` URL 放進要求主體。 |
| `efforts` | 此卡片的思考層級，依下拉式選單的順序。名稱可自由填寫。 |
| `defaultEffort` | 新工作階段開始時使用的層級。它必須是此卡片 `efforts` 中的一個。 |

Spinney 不做任何探查。內容視窗、影像支援和傳輸方式都由你宣告。`contextWindow` 填錯會讓 `ctx` 讀數大小不對。

內建的列無法刪除。你可以編輯它們。

### 6.3 選擇模型

模型和推理力度屬於節點，不屬於分頁：

1. 一個回合儲存它執行時所用的卡片和層級。
2. 後續訊息使用最近上層節點的卡片和層級。
3. 新工作階段從 `spinney.model` 開始，或從內建的 `deepseek-flash` 卡片開始。

在下拉式選單中的選擇會更新即時設定，而新節點會凍結該即時設定。繼續一段已凍結對話的傳送會保留凍結的設定，並先詢問（第 3.4 節）。簽出會捨棄這次選擇，下拉式選單會跟隨簽出的節點。

模型、推理力度或回覆語言的變更絕不會重寫已凍結對話的設定。新值適用於下一個新節點。

當工作階段中有任何回合在執行時，這兩個下拉式選單會停用。

## 7. 推理力度

推理力度下拉式選單包含作用中卡片的層級。每張卡片有自己的清單。切換卡片時，清單也跟著切換。

層級 `none` 很特別。它完全不傳送 `reasoning_effort`，而且系統提示會少了推理力度那一句。

Spinney 絕不傳送卡片沒有宣告的層級。卡片沒有提供的層級會退回該卡片的 `defaultEffort`，不會顯示任何訊息。

## 8. 子代理與背景終端

### 8.1 子代理

代理用 `spawn_agents` 工具啟動子代理。每個子代理平行執行自己的對話。它的卡片位在父卡片旁邊，並帶有 `SUB` 標記。

| 事項 | 細節 |
|---|---|
| 深度 | 兩層。子代理不能啟動更深的一層。 |
| 數量 | 同時可有 `spinney.maxConcurrentSubagents` 個第 1 層子代理（預設 15）。多出的工作會在佇列中等待。 |
| 第二層 | 每個子代理最多啟動 `spinney.maxLevel2Subagents` 個子項（預設 2）。 |
| 模式 | 可寫的子代理可以變更檔案和執行命令。唯讀的子代理只能讀取。 |
| 卡片 | 標記列顯示深度、模型，以及 `write` 或 `ro`。**✕** 按鈕會終止它。卡片也會顯示這次執行的耗時。子代理執行期間該數字會持續變動，執行結束後仍會留在卡片上。 |
| 結果 | 子代理結束時，Spinney 把通知遞送給父節點。通知會帶有這次執行的耗時。卡片會顯示 `Delivered`。 |
| 回報 | Spinney 在父回合的下一個工具邊界遞送通知。當父節點閒置時，Spinney 把通知注入父節點。它絕不會建立新節點。 |

一個子代理批次等待的時間同樣不超過 `spinney.commandMaxForegroundDuration`。批次在該上限時仍在執行，`sync` 模式（預設）下的 `spawn_agents` 和 `send_agent_message` 就會傳回代理 id。所有摘要之後會以單一批次通知送達。

你無法在子代理卡片中輸入。若要繼續已結束的子代理，請要求父代理去做。

按 **停止** 時，Spinney 終止該節點的整個子代理子樹。它把待遞送的通知寫入該節點的歷史。已停止的子代理絕不會自行恢復。

重新啟動後，原本在執行的子代理會顯示為 `已終止`。

### 8.2 背景終端

背景終端在回合繼續時保留一個長時間執行的命令。代理透過帶有 `timeout_behavior` 的 `exec_command` 啟動一個背景終端。

任何操作佔用一個回合的時間都不會超過 `spinney.commandMaxForegroundDuration`（300 秒，即 5 分鐘）。`exec_command` 的 `timeout` 是命令的全部預算：前景時間加背景時間，沒有上限。`timeout` 長於該上限時，不會啟動任何東西，呼叫會先被拒絕，除非它同時傳入一個背景取值。

`timeout_behavior` 決定該呼叫是什麼身分。它有四個取值：

| 取值 | Spinney 啟動什麼 | 代價是什麼 |
|---|---|---|
| `stop_when_timeout` | 不啟動任何東西。命令達到逾時時間時仍在執行，Spinney 就會終止它。該取值是預設值。 | 沒有代價。 |
| `background_when_timeout` | 在該節點上啟動一個工作。命令先在前景執行，最多到 5 分鐘上限，隨後 Spinney 把它移到背景。預算的剩餘部分就是該工作的預算。該呼叫必須傳入 `timeout`。 | 該工作結束前，該節點不能傳送訊息。工作結束時 Spinney 傳送一則完成通知。 |
| `start_in_background` | 立即在該節點上啟動一個工作。全部預算就是該工作的截止時間。該呼叫必須傳入 `timeout`。 | 與上一列相同。 |
| `start_detached` | 立即啟動一個分離工作。該工作不鎖定任何節點。`timeout` 可以省略。 | 該節點保持空閒，而且該工作不傳送通知，所以代理只在主動查詢時才知道它的結果。該工作階段中的任何節點都能讀取或終止該工作。 |

預算用盡時，Spinney 終止該工作。`background_when_timeout` 和 `start_in_background` 都需要 `timeout`：未傳入 `timeout` 時，Spinney 不會啟動任何東西，呼叫會先被拒絕。沒有截止時間的工作會一直佔用它的節點，所以那樣的工作屬於 `start_detached`。拒絕訊息會指出呼叫要求的取值，說明沒有啟動任何東西，並給出兩條出路：傳入 `timeout`，或改用 `start_detached`。只有 `start_detached` 可以沒有截止時間，因為它不鎖定任何節點。`join_background` 同樣不得讓一個回合超過該上限：只要該工作剩下的預算還多於該上限，或根本沒有截止時間，join 就會被拒絕，並告知代理結束本回合，完成通知之後才會到達。Spinney 也會拒絕分離工作的 join：該工作沒有截止時間，也不傳送通知，所以沒有任何可等待的東西。代理用 `check_background_terminal` 讀取分離工作，用 `kill_background` 結束它。`check_background_terminal` 和 `kill_background` 對每個工作都可用。

代理不會自己把進程放到背景，例如用 `&` 或 `Start-Process`。Spinney 無法追蹤這樣的進程，你也不能從卡片上終止它。

卡片顯示 `#<id>`、狀態、經過時間、命令，以及最後幾行輸出。命令執行期間，經過時間會變動，命令結束後仍會留在卡片上。命令的結果也會告訴代理該命令花了多久。分離工作會顯示 `shared` 徽章：該徽章表示該工作即發即忘，所以卡片從不等候代理。

| 狀態 | 含義 |
|---|---|
| `執行中` | 命令正在執行。**終止** 按鈕可以使用。 |
| `待遞送` | 命令已結束。通知在等代理。 |
| `結束碼 {0}` | 命令的結束碼。 |
| `已終止` | Spinney 或你終止了處理程序樹。 |
| `已結束` | 紀錄的結尾。 |

分離工作從不顯示 `待遞送`，因為它不傳送通知。

背景工作屬於啟動它的節點。它不會鎖住另一條分支或另一個工作階段。`#id` 是工作階段的計數器，不是作業系統的 pid。

工作結束時，Spinney 以遞送子代理通知的相同方式遞送通知。之後，卡片保留為帶有 `Delivered` 標記的紀錄。

Spinney 會在這些情況下終止正在執行的工作：

- 你在擁有該工作的節點上按 **停止**。
- 你刪除分支或工作階段，或清除對話。會先跳出一個強制回應視窗詢問。
- 你關閉視窗。

重新啟動後，原本在執行的工作會顯示為 `已中斷`。卡片不會在並非進行中時顯示為進行中。

子代理可以啟動背景終端，但無法管理背景終端。只有你能終止它。

## 9. 圖片

用 **附加圖片** 按鈕附加圖片，或把圖片貼到輸入方塊中。待處理的附件會顯示為小圖片，並帶有 **×** 按鈕。

只有 `vision.enabled` 的卡片接受影像。Spinney 內建的 `deepseek-flash` 已開啟影像支援。

| 情況 | 會發生什麼 |
|---|---|
| 卡片沒有影像支援 | 附件會被拒絕：`切換到支援影像的模型（{0}）即可附加圖片。` |
| 沒有任何卡片支援影像 | `沒有設定支援影像的模型 — 請在某張模型卡片上啟用視覺支援以附加圖片。` |
| 你切換到不支援影像的卡片 | Spinney 隱藏歷史中的圖片。它保留資料，並在支援影像的卡片回來時還原。 |
| 傳輸方式是 `deepseek` | Spinney 先上傳圖片。狀態列接著顯示 `正在上傳圖片…`。**停止** 會中止那次傳送。 |
| 上傳失敗 | `無法上傳：{0}。這些圖片已被略過。` |

影像最大可達 64 MiB。格式有 JPEG、PNG、GIF 和 WebP。Spinney 從內容讀取格式，不從檔名讀取。

已上傳的影像無法移到另一個供應商。`file_id` 只屬於產生它的供應商。卡片會顯示 `[image hidden: it was uploaded to a provider that this model cannot read from]`。`openai` 傳輸方式沒有這個問題。

## 10. 錯誤、重試與繼續

### 10.1 自動重試

Spinney 最多重試一個要求 10 次。等待時間是 1 秒、2 秒、4 秒，依此類推，上限為 30 秒。

狀態列顯示 `模型呼叫失敗（{0}/{1}）；{2} 後重試…`。第一個數字是失敗的那次嘗試。

Spinney 重試這些失敗：

- 網路錯誤。
- HTTP `408`、`429`，或任何 `5xx`。
- 主體為空的 `200` 回應。

Spinney 不重試這些失敗：

- HTTP `400`、`401`、`403`、`404` 或 `422`。這些無法自行修復。
- 串流中斷。重試會重複輸出。
- 影像上傳。
- 餘額讀取。

在等待期間按 **停止** 會立即結束重試。

停滯的要求有時間上限。Spinney 等第一個位元組 20 秒、等第一個區塊 20 秒，區塊之間等 60 秒。停滯的要求顯示 `思考中…`，且 `tok/s` 為 0。

### 10.2 卡片按鈕

已結束的卡片可能有一個按鈕，也可能同時有兩個，共三種。按鈕取決於節點的狀態。

| 節點狀態 | 按鈕 | 功能 |
|---|---|---|
| `已中斷` | **▶ 繼續** | 傳送一則 harness 訊息，並在同一個卡片中繼續該回合。部分輸出會保留。 |
| `錯誤` | **↻ 重試** | 傳送一則 harness 訊息，並從該節點重新執行該回合。失敗回合的部分輸出會被捨棄。 |
| `錯誤`，內容達到 90% 或以上但未滿 | **↻ 重試** 和 **⧉ 在新視窗中繼續** | 兩個按鈕。重試在本視窗中重新執行該回合。另一個提供新視窗。它的工具提示顯示百分比。請參閱第 10.3 節。 |
| `已中斷`，內容達到 90% 或以上 | **⧉ 在新視窗中繼續** | 提供一個新的內容視窗。工具提示顯示百分比。請參閱第 10.3 節。 |
| `錯誤`，內容已滿 | **⧉ 在新視窗中繼續** | 開始新的內容視窗。內容視窗可能因 token 已滿，也可能因影像位元組已滿。請參閱第 10.3 節。 |

按鈕負責這件工作。你不需要自己輸入指示。

### 10.3 內容視窗已滿

當供應商以內容長度錯誤回應時，內容視窗就已滿。要求也會帶著其中的影像，形式是已上傳的位元組。供應商把這些位元組的上限設為每個要求 200 MB。因為這個原因被拒絕，也算內容視窗已滿。例如，訊息是 `Total image size exceeds the limit: max 200 MB per request, got 203 MB`。Spinney 不從 `ctx` 讀數猜測限制。卡片顯示 **⚠️** 訊息，按鈕變成 **⧉ 在新視窗中繼續**。

在失敗之前，Spinney 也會提供這個按鈕。回合結束但沒有回答的卡片，在卡片的 `contextWindow` 用到約 90% 時就會提供它。工具提示帶有這個數字，例如 `Context 93% full - continue in a new window`。這是建議，不是修復。沒有任何東西失敗時，按鈕單獨出現。在 90% 或以上失敗的卡片會把它顯示在 **↻ 重試** 旁邊：供應商沒有拒絕任何內容，因此兩個動作都保留。

兩種情況下，Spinney 都會問新節點必須以哪個設定開始（第 3.4 節）：

- `Continue with current setup`。新節點沿用其上方對話的設定。
- `Continue with latest setup`。新節點凍結最新設定。

這裡兩種回答都不付出代價。新的內容視窗從空白開始，因此沒有可失去的快取前綴。

1. 點選 **⧉ 在新視窗中繼續**。如果該節點仍擁有正在執行的工作，會先跳出一個強制回應視窗詢問。它會列出將停止的工作。
2. Spinney 在該節點下方開啟新卡片。邊線是虛線，標題是 `內容視窗 {0}`，標記是 `CTX`。

新的視窗以系統提示和一則 harness 訊息開始。該訊息包含你的最後一個要求和最後一個回答，並經過縮短。沒有其他內容送到模型。附件無法跨越，因此訊息只列出它們的名稱。

舊分支仍可使用。你可以再次傳送到它，或在那裡按 **▶ 繼續**，直到它再次溢出。

`CTX` 的工具提示是 `此節點會開啟新的內容視窗；其上方分支不會再傳送給模型`。

兩個不是故障的細節：

- 新卡片不帶固定的使用者訊息。由 harness 開啟的回合沒有這種訊息。
- 無論顯示語言是什麼，harness 的文字都是英文。

## 11. 設定參考

## 13. 工作區指示

Spinney 讀取工作區根目錄的 `AGENTS.md`，並把它加入系統提示。用它記錄你專案的規則，例如測試命令或程式碼風格。

兩個要知道的事實：

- Spinney 在擴充功能主機啟動時讀取該檔案一次。編輯不會送達執行中的視窗。變更檔案後請重新載入視窗。
- 未開啟資料夾時，Spinney 不讀取任何內容。

執行 **`Spinney: 顯示系統提示`** 可閱讀模型實際收到的確切提示。內容依目前的模型卡片、推理力度、回覆語言，以及該工作階段的 `AGENTS.md` 快照而定。

## 14. 隱私與資料

Spinney 不傳送任何遙測。它只連線到你設定的供應商端點。

一個要求帶上你的訊息、工具結果和圖片。餘額讀取會對供應商多發一個要求。影像會依卡片的傳輸方式，以檔案上傳或放在要求主體中送到供應商。

擴充功能不保留已上傳影像位元組的副本。

| 內容 | 位置 |
|---|---|
| 對話 | VS Code 狀態資料庫，不是檔案。工作區一列，未開啟資料夾時則為設定檔一列。 |
| 逐字稿 | JSONL 檔案，每個已結束的回合一個，每個子代理一個。資料夾：擴充功能儲存區，或 `spinney.subAgentTranscriptDir`。 |
| 大型工具結果 | `<agent root>/.spinney/tool-output/`。 |
| API 金鑰 | VS Code 密鑰儲存區，由作業系統加密。絕不寫入 `settings.json`。 |
| 設定 | `settings.json`。模型卡片頁面寫入 Global 範圍。 |

Spinney 不寫入你的 `.gitignore`。如果你不想讓寫入磁碟的工具輸出進入提交，請自行加入 `.spinney/` 資料夾。

解除安裝後，對話仍留在狀態資料庫中。第 15 節會移除它們。

### 14.1 HTTP 控制平面

控制平面預設為關閉。它接聽 `127.0.0.1`，並需要持有人權杖。

它為外部控制器而存在。`POST /continue` 讓代理執行來自呼叫方的指示。請把該連接埠視為你機器的信任邊界。只在需要時才開啟它。

控制平面開啟時，Spinney 把連接埠和權杖寫入 `<extension storage>/http/<instanceId>.json`。

## 15. 解除安裝與清除資料

1. 為每個供應商執行 **`Spinney: 清除 API 金鑰`**，或接受密鑰會保留。
2. 從擴充功能檢視解除安裝 Spinney。
3. 手動刪除資料夾 `<extension storage>/de-yu.spinney`。它包含逐字稿、備份和控制平面檔案。
4. 也刪除對話的列。在狀態資料庫中，設定鍵是 `DE-YU.spinney`。一列位於 `globalStorage/state.vscdb`，另一列位於每個 `<workspaceStorage>/<hash>/state.vscdb`。

注意這兩種拼法：資料夾名稱是小寫，而列設定鍵保留擴充功能 id 的大小寫。

你導向自己資料夾的檔案不在這些步驟範圍內。請檢查 `spinney.subAgentTranscriptDir` 和任何 `.spinney/` 資料夾。

## 16. 無資料夾模式

Spinney 可以在未開啟資料夾的視窗中運作。

- 工具呼叫中的相對路徑，對照擴充功能儲存區中的暫存資料夾 `<extension storage>/no-workspace` 解析。代理用絕對路徑存取你真正的檔案。
- 工作階段位於設定檔，不在工作區。同一設定檔的每個無資料夾視窗都顯示相同的工作階段。請一次只使用一個視窗。
- Spinney 不讀取 `AGENTS.md`，因為沒有工作區根目錄。
- 寫入磁碟的工具結果放到 `<scratch folder>/.spinney/tool-output/`。

在同一個視窗中開啟資料夾，或關閉資料夾，Spinney 會立即切換模式。

## 17. 疑難排解

| 症狀 | 原因與修正 |
|---|---|
| `No API key configured for this provider.` | 用 `Spinney: 設定 API 金鑰` 設定金鑰，或為具名供應商在模型卡片頁面上設定。 |
| 要求立即失敗，沒有重試 | `400`、`401`、`403`、`404` 或 `422`。請閱讀訊息。常見原因是金鑰錯誤和模型名稱錯誤。 |
| 狀態列不斷重複 `retrying` | 網路故障、`429` 或 `5xx`。狀態列無法分辨連線中斷與供應商錯誤。按 **停止** 結束等待。 |
| `思考中…`，且 `tok/s` 為 0 持續很久 | 串流停滯。監看機制會在 20 秒到 60 秒後結束它。 |
| `ctx N%` 看起來不對 | 它把**上一次**要求的提示 token 除以卡片的 `contextWindow`。請檢查卡片的值。 |
| 沒有餘額數字 | 供應商的 `balance` 值是 `none`，或讀取失敗。Spinney 只讀取餘額一次，絕不重試。 |
| 代理忽略 `AGENTS.md` 中的新規則 | 重新載入視窗。Spinney 每次啟用時只讀取該檔案一次。 |
| 圖片無法附加 | 作用中的卡片沒有影像支援。為卡片加上 `vision`，或切換到支援影像的卡片。 |
| 回合在開始前等待 | 並行閘門。狀態列會說明等待的原因。調高供應商或卡片上的 `concurrency`，或等待。 |
| 模型下拉式選單是灰色的 | 本工作階段有回合正在執行。停止它或等它結束。 |
| 檢視停在舊卡片上 | 手動平移或縮放關閉了跟隨模式。點選 **跟隨作用中節點**。 |

**Spinney** 輸出通道包含診斷資訊。用 View → Output 開啟它，然後在清單中選取 `Spinney`。它會列出顯示語言、模型設定問題，以及版面和效能相關的行。

執行 **`Spinney: 顯示系統提示`** 可查看確切的提示，執行 **`Spinney: 顯示使用者手冊`** 可重新開啟本手冊。


## 18. 回報卡頓或異常

Spinney 為每個視窗保留一份診斷記錄。其中只有耗時、計數與路徑——不含你輸入的內容，也不含 API 金鑰。

記錄的每一行都以時間戳結尾，例如 ` | at=2026-09-21T04:14:48.123Z`。記錄也會在命令開始時寫一行、命令執行期間每 30 秒寫一行心跳，並在命令結束時寫一行。因此，卡住的命令事後可以在記錄中看到。記錄也會寫下背景工作的預算：Spinney 登記該工作時寫一行（`bg register … budget=…`），預算用盡時再寫一行（`bg expire …`）。

| 步驟 | 做法 |
|---|---|
| 1 | 重現問題。 |
| 2 | 執行 `Spinney: 開啟診斷記錄`，然後按 **在檔案總管中顯示**。 |
| 3 | 把那一份檔案寄給支援你的人。 |

從輸出面板複製的文字不是同一份檔案：它沒有檔案標頭那一行，而該行會寫明建置、處理程序與視窗的啟動時間。

把 `spinney.diagnostics.log` 設為 `false` 可以停掉它。

Spinney 沒有啟動的處理程序可能殘留。當一個命令把工作交給另一個程式時就會發生，例如編輯器、建置伺服器或測試橋接程式。該程式的子處理程序在 Spinney 的處理程序樹之外。**停止** 無法觸及它，它的輸出也永遠不會回來。Spinney 無法替你找到這樣的處理程序。請使用工作管理員，或在 PowerShell 中執行下列命令：

```powershell
Get-CimInstance Win32_Process -Filter "name like '<program>%'" | Where-Object { $_.CreationDate -lt (Get-Date).AddHours(-2) } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

把 `<program>` 替換為殘留處理程序的名稱。該篩選條件會比對啟動超過兩小時的處理程序。

## 19. 網路搜尋

Agent 可以搜尋網路，並讀取一個頁面。這兩個工具都不需要 API 金鑰，也不需要任何設定。

| 工具 | 作用 |
|---|---|
| `web_search` | 把查詢送給一組搜尋後端，回傳編號的結果清單：標題、網址與摘要。 |
| `web_fetch` | 讀取一個網址，回傳該頁面的文字。HTML 頁面會轉換成 Markdown。 |

搜尋後端是內建的。Spinney 依此順序嘗試：Bing (RSS)、360、百度、搜狗、Bing (HTML)、Hacker News、StackExchange、GitHub。結果中會寫明由哪個後端作答，以及其餘後端各自的結果。

兩條規則讓搜尋保持可用：

- 後端回傳驗證碼或驗證頁面時，Spinney 會標記該後端，並在一段時間內跳過它；重複失敗後跳過的更久。
- 網路不同，可用的後端也不同。部分地域無法連上 DuckDuckGo、Google、Mojeek 和 Wikipedia；另一些地域存取百度、搜狗和 360 時會遇到驗證碼。

搜尋沒有結果時，請執行 **`Spinney: 測試網路搜尋後端`**。Spinney 會向每個後端送出一次測試查詢，並開啟一張表，列出各自的結果、耗時與命中數。該命令只做量測，不修改任何設定。

`web_fetch` 會跟隨一次轉址，最多讀取 2 MB，並使用頁面本身的字元集。它不執行 JavaScript。由瀏覽器動態產生的頁面只會回傳很少的文字，結果中會說明這一點。`web_fetch` 會拒絕私有位址，例如 `localhost` 和 `127.0.0.1`。

頁面的文字不是對 Spinney 的命令。Spinney 把它視為陌生人的資訊。若頁面試圖對 Spinney 下達指令，Spinney 會向你回報。

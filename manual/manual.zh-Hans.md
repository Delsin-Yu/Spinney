# Spinney 用户手册

Spinney 是一个 VS Code 扩展。它把智能体放进一个编辑器标签页，并把对话保存成一棵可以分支的树。

Version: 0.0.2.

## 1. 安装与首次运行

1. 从 Visual Studio Marketplace 安装 **Spinney**。
2. 在 Activity Bar 中打开 **Spinney** 容器。它包含 **会话** 视图。
3. 点击视图标题栏中的 **Spinney: 新建会话**。一个标签页打开，标题为 `智能体聊天树 — 新会话`。
4. 设置 API 密钥（第 2 节）。然后在底部的输入框中写下第一条消息，并按 **Enter**。

`Shift+Enter` 新起一行。`Enter` 发送。

Spinney 在打开文件夹和未打开文件夹时都能工作。见第 16 节。

全新配置档案运行内置模型卡片 `deepseek-flash`。你可以更改它（第 6 节）。

## 2. 设置 API 密钥

Spinney 把密钥保存在 VS Code 密钥存储中，绝不保存在 `settings.json` 中。

1. 用 `Ctrl+Shift+P` 打开命令面板。
2. 运行 **`Spinney: 设置 API 密钥`**。
3. 在提示处粘贴密钥并确认。

VS Code 用 `Spinney：API 密钥已保存。` 确认。密钥立即生效。你不需要重新加载窗口。

运行 **`Spinney: 清除 API 密钥`** 可清除密钥。

两条特殊规则：

- 内置服务商也接受 `DEEPSEEK_API_KEY` 环境变量。只有在没有已保存的密钥时，Spinney 才使用该变量。
- 有多个服务商时，请在模型卡片页面（第 6 节）中、在该服务商那一行里设置每个密钥。

没有密钥时，每个请求都会失败，并显示 `No API key configured for this provider.`。Spinney 每个窗口显示一次 `设置 API 密钥` 按钮。

## 3. 聊天窗口

树中每个回合有一张卡片。新回合放在它所回答的那个回合下方。输入区就是输入停靠区。它位于你检出的那张卡片内部。

### 3.1 输入区

| 控件 | 作用 |
|---|---|
| 输入框 | 保存你的消息。`Enter` 发送，`Shift+Enter` 换行。 |
| **发送** | 发送消息并开始一个回合。这个按钮在四种情况下禁用：输入框为空、上下文窗口已满（第 10.3 节）、本窗口为只读，或检出的节点是子智能体分支。`Enter` 只通过这个按钮发送，因此按钮禁用时按 `Enter` 不发生任何动作。 |
| **压缩…** | 在任何填充度下开始新的上下文窗口（第 10.4 节）。点击后问两个问题：**Simple**（指针式交接，不额外花请求）或 **Agentic**（压缩回合），然后新窗口用哪套设置。在只读窗口和子智能体分支上禁用；**停止** 显示时隐藏。工具提示为 `Move this conversation into a new context window: a pointer (Simple) or a compression turn (Agentic). The harness asks which, and which setup the new window uses.` |
| **新设置…** | 仅当输入区显示的设置与已冻结的设置不同时出现（第 3.4 节）。点击后按当前设置继续这段对话，并让树分叉，旧树保留自己的字节。工具提示为 `Continue this conversation under the setup the composer shows now. The tree forks, so the old one keeps its own bytes.` |
| **停止** | 在检出的节点结束该回合。它也会终止该节点的后台终端和子智能体。没有任何内容继续。工具提示为 `停止这一轮` 或 `停止这个节点：终止它的后台任务与子代理（不会给模型发送任何内容）`。 |
| 提示词片段 | 打开一个预写指令菜单。点击会把文本插入输入框。不会发送任何内容。Spinney 自带 `Plan` 和 `Implement Parallel`。用 `spinney.promptSections`（第 11 节）添加你自己的行。 |
| **附加图片** | 打开文件选择器。你也可以把图片粘贴到输入框。见第 9 节。 |
| 模型下拉列表 | 为新节点选择模型卡片。继续这段对话的发送会保持冻结的配置（第 3.4 节）。列表按服务商对卡片分组。 |
| 齿轮按钮 | 打开模型卡片页面。工具提示为 `管理模型卡片…`。 |
| 推理力度下拉列表 | 选择推理级别。该列表即当前卡片的列表。 |

**发送** 和 **停止** 是同一个按钮，有两种含义。当检出的节点正在运行一个回合，或该节点仍拥有未完成的工作时，按钮显示 **停止**。**停止** 会替换所有其他按钮，因此它显示时 **发送**、**压缩…** 和 **新设置…** 都会隐藏。

当后台终端或一批子智能体在运行，或有完成通知在等待该节点时，该节点就拥有未完成的工作。你不能向这样的节点发送。没有队列。请先按 **停止**，或从另一个节点发送。

另一个分支或另一个会话可以同时运行。它不会阻塞这个输入区。

子智能体卡片没有输入区。它的分支是只读的，横幅显示 `子智能体分支（只读）— 由主智能体通过 spawn_agents / send_agent_message 驱动`。

### 3.2 树的工具栏与手势

工具栏有两个按钮：

- **跟随活动节点**（`⦿`）。视图让正在流式输出的节点保持在屏幕上。
- **适应视图大小**（`⤢`）。

| 手势 | 结果 |
|---|---|
| 滚轮 | 滚动视图。 |
| `Ctrl`+滚轮 | 缩放。 |
| `Alt`+滚轮 | 上下平移。在卡片或输入区上也有效。 |
| `Shift`+滚轮 | 横向平移。 |
| 中键拖动 | 平移。 |
| 按住右键 | 朝指针方向平移。 |
| 拖动卡片的右下角 | 调整该卡片的大小。 |
| 右键点击卡片标题 | 打开卡片菜单。它包含 `复制节点 ID`。 |

手动平移或缩放会关闭那个按钮。

每个卡片标题都带有回合标题、一个状态标签和一个 **🗑** 按钮。该按钮删除该回合处的分支（第 4 节）。

卡片主体从上到下有两个部分。

第一部分保存你的消息。Spinney 始终显示这一部分，且从不折叠它。Spinney 以 Markdown 呈现这一部分。

第二部分是工作日志。只有它会滚动。工作日志按回合发生的顺序保存这一回合的每一行。最终回答是工作日志的最后一块，并以 Markdown 呈现。

步骤可以折叠。一个回合可以显示一个或多个步骤组。工具行开启一个组。模型的文本块结束这个组。组的标题是 `执行了 N 步`，只有一次调用时是 `执行了 1 步`。思考行也算一步。组里的工具行位于标题下方，并且带有缩进。组里的思考行同样缩进。组里保存思考行、工具行、通知、后台任务通知和 `HARNESS` 块。一轮的思考行都在它的组里，包括第一次工具调用之前的那一段。模型在途中写下的文本留在工作日志里，位于两个组之间。回合运行时组是展开的。回合结束后每个组都会折叠。点击标题可以展开这个组或收起它。你手动展开或收起过的组会保持你留下的状态。工作日志带有一个绿色圆点。该圆点表示跟随模式。圆点为绿色时，Spinney 跟随最新内容。圆点为绿色时你仍然可以滚动。向上滚动时，圆点变暗，Spinney 停止跟随。滚动回末尾时，圆点重新变绿。要立即恢复跟随，请点击暗色圆点。点击绿色圆点可停止跟随模式。正在进行的回合开始时，圆点为绿色。已结束的回合开始时，圆点为暗色。该圆点位于工作日志滚动条的正中。后台任务或子代理批次结束时，节点会继续第二轮。每一轮都有自己的步骤组。

两种行承担这一回合的工作。

思考行保存模型的思考。该行以标签 `思考` 开头。标签是粗体、斜体和暗色。回合运行时，该行是展开的：标签独占一行，段落位于它下方。段落不倾斜。段落是暗色的。Spinney 把思考行缩进，与工具行一致。段落有最大高度，很长的推理不会把这一回合的其余内容推下去。在段落内滚动可读到其余部分。展开的段落右下角带有自己的绿色圆点。该圆点表示该段落的跟随模式。向上滚动该段落时，它的圆点变暗。后面的文本不会把段落移回原处。点击暗色圆点可再次跟随最新文本。点击该圆点不会展开或收起该行。回合结束后，它变为一行。标签是这一行的第一部分。思考的开头是第二部分，使用斜体和暗色。点击该行可展开它。展开的行显示全部文字和 token 行。Spinney 按模型写下的原样显示文字。再次点击可收起它。你点击过的行会保持你留下的状态。

工具行保存一次工具调用：一个动词、一个标签，以及一个时间。粗体动词位于行首，例如 `读取文件`、`编辑文件`、`运行命令` 或 `搜索文件`。标签是智能体为这一步给出的短名称。智能体没有给出名称时，标签是路径、命令、模式或会话。动词和标签都使用淡的文字颜色。动词和标签还是倾斜的。命令和模式的标签使用等宽字体和更小的字号。该标签不倾斜。时间显示这次调用的用时。调用运行时它持续更新，调用结束时停止。智能体还在编写这次调用时，该行显示固定标签 `正在编写工具调用…`。调用开始时，动词、标签和时间替换这个标签。文件工具的行还会显示这次调用改动的行数。新增的行数是绿色，前面带 `+`。删除的行数是红色，前面带 `-`。为零的数字不显示。没有改动任何行的调用，两个数字都不显示。点击该行可展开这次调用。Spinney 按工具的形状显示这次调用。文件带行号显示。改动以 diff 的红绿行显示。命令以终端形状显示输出。目录显示其条目。图片显示为图像，点击会在编辑器中打开该文件。文件结果顶部的路径点击可打开该文件。目录列表里，点击文件会打开该文件。文件夹没有点击。搜索把每次命中显示为文件、行号和文字，点击会在该行打开该文件。会话树的列表显示节点数量。会话调用显示目标会话、它发出的文字，以及剩下的回合数。收起的那一行也显示回合数。重命名或交接显示一句话。开启新一轮的完成通知是一行朴素文字，那一轮的步骤跟在它后面。点击这一行可以看到这一批的摘要。回合中间的完成通知则像工具行一样显示为一行：标签点明是谁产出的，输出点一下就展开。调用的参数显示为一行文字，绝不显示 JSON。文字使用更小、更淡的字体。调用返回错误时，后面显示错误文本。token 行位于最后。再次点击该行可收起它。

卡片不会随着每一步变高，而是在工作日志内部滚动。拖动卡片的右下角可以让工作日志更高。

卡片最高可达 840 像素。

子智能体卡片和后台任务卡片是紧凑的监看卡片：高度固定为 200 像素。它显示该子智能体的实时进度：状态、计数器和它工作日志的末尾。它不显示整张卡片的全部内容。Spinney 以完整高度打开你正在阅读的那张子智能体卡片，那张卡片显示全部内容。其他卡片保持紧凑。Spinney 把同一个节点旁边的卡片填入一栏，一栏放三张；一栏排满时，就在右侧另起一栏。子智能体的子智能体卡片在它们自己的栏中，位于右侧。节点下方的对话因此不会被推得很远。子智能体卡片显示它所属家族的颜色。由它派生的卡片使用相同的颜色，但饱和度更高、亮度更低。子智能体卡片使用暖色。后台任务卡片使用冷色。

按 `Ctrl+Alt+D` 把布局诊断写入输出通道。

### 3.3 状态行

输入框下方那一行显示会话的状态。

| 项目 | 含义 |
|---|---|
| 状态圆点 | 会话空闲时为暗色。有任何内容流式输出时呈琥珀色并脉动。 |
| 状态行 | `就绪`、`思考中…`、`正在上传图片…`、`正在停止…`、`已中断`、`错误`，或一条重试消息（第 10 节）。 |
| `ctx N%` | 上下文窗口用量。它用**上一次**请求的提示 token 除以卡片的 `contextWindow`。它是一个读数，不是限制。它可能出错。 |
| `bal …` | 正在应答的服务商的余额。`bal –` 表示不存在数字，例如在余额方言为 `none` 的服务商上。Spinney 只读取一次余额，且从不重试。 |
| `tok/s` | 输出速度。它是本地估算，不是服务商的计数。 |

每一步都有自己的 token 行：`[提示: 1200 + 补全: 340, 缓存命中: 1000, 缓存未命中: 200]`。它显示这次请求的提示 token 数、补全 token 数、缓存命中数和缓存未命中数。

一个 `HARNESS` 块保存 harness 发给模型的准确文本。`HARNESS` 块与其他步骤一起位于工作日志中。

回复里可以带文件链接。点击链接会在编辑器标签页中打开该文件。标签页会选中链接指定的行，并把它们显示在编辑器中央。链接可以指定一行，也可以指定一个行范围。链接中的路径相对于工作区根目录。没有行号的链接从文件开头打开。例如 `src/extension.ts:12-20` 打开该文件并选中第 12 到 20 行。

有意保持英文的代码：`SUB`、`BG`、`CTX`、`HARNESS`、`Delivered`。

### 3.4 冻结的配置与多棵树

对话冻结在它开始时使用的配置上。该配置包含模型卡片、推理级别、回复语言，以及随扩展发布的系统提示词。一次普通的发送始终使用该冻结的配置。

选择另一张模型卡片、另一个推理级别或另一种回复语言，会让实时配置与冻结的配置不同。此时输入区会同时显示这两种配置，各占一行：

- `Sending with: {0}`。一次发送真正使用的配置。
- `New setup: {0}`。新节点将冻结的配置。

其中的值包含卡片、推理级别和回复语言。例如：`Sending with: deepseek-flash · medium · English`。

Spinney 不会在普通发送时问这个问题。普通发送始终使用冻结的配置。上面两行身份说明就写明了这一点，而冻结的配置会保留服务商的提示词缓存。

发送按钮旁边有两个入口，各回答一个问题。**压缩…** 在任何填充度下把这段对话移到新的上下文窗口：它先问要用哪种交接（第 10.4 节），再问新窗口用哪套设置。**新设置…** 只在输入区显示的设置与已冻结的设置不同时出现：它按当前设置继续这段对话，并让树分叉，旧树保留自己的字节。

点击 **新设置…** 会问 `Continue with the new workspace or model configuration?`。文本会给出历史记录的 token 数量。回答是 **Continue**。Spinney 把这棵树复制成一棵新树，新树以最新配置开始。旧树保留它自己的配置与提示词缓存。

点击 **压缩…** 会问 `Start a new context window?`，选项是 **Simple** 和 **Agentic**（第 10.4 节）。两套设置不一致时，会再问一次 `Which setup does the new window continue on?`，选项是 **Keep this window’s setup** 和 **Use the latest setup**。

按 `Escape`，或点击关闭按钮，即可关闭这个问题。被关闭的问题不发送任何内容、不终止任何内容，Spinney 会把你输入的文字留在输入框中。Spinney 在执行之前会再次检查状态，因此在问题打开期间发生的变化不会发送任何内容，并会显示一条消息。

一个会话可以容纳多棵树。Spinney 把新树放在当前树旁边。视图并排显示这些树，并把视图移到新树，每棵树都可以交互。检出你想继续的那棵树中的节点，然后发送。

### 3.5 重新加载聊天视图

聊天标签页可能显示对话的旧画面。例如某个卡片不再变化，或只显示树的一部分。对话是正确的，正在运行的回合也会继续。

运行 **`Spinney: 重新加载聊天视图`**，从会话的状态重新构建该标签页。当标签页显示冻结的画面，或某个卡片不再变化时，使用此命令。

该命令不会改变对话。它不会停止正在运行的回合。没有打开的聊天标签页时，Spinney 会回答 `Spinney：此窗口没有打开的聊天标签页。`

## 4. 分支

### 4.1 从回合创建分支

1. 点击你想从中分支的回合标题。卡片展开，输入区移入其中。
2. 写新消息。当该回合已经有子节点时，横幅显示 `⤷ 从 {0} 分支 — 你的回复将开启一个新分支`。
3. 按 **Enter** 或点击 **发送**。

新回合成为同级分支。Spinney 不删除任何内容。旧的那条线在树中保留为变暗的单行卡片。点一次就能把它调回来。

检出没有代价。你可以在一个回合流式输出的同时检出另一个回合。检出移动的是视图，不是正在运行的回合。

也可以从已经发送过的提示词创建分支。点击卡片中问题右上角的铅笔。问题会变成一个输入框。修改文字，然后按 **Enter**。Spinney 把修改后的文字作为一个新分支发送，分支从该卡片上方的回合开始。原来的回合作为同级分支留在树中。按 **Shift+Enter** 换行。按 `Escape` 或点击别处取消。原提示词中的图片会随修改后的提示词一起保留。回合运行期间也可以这样改。新分支从卡片上方的回合开始，正在运行的回合不变。

### 4.2 删除分支

1. 把鼠标悬停在开启该分支的回合标题上。
2. 点击 **🗑**。工具提示为 `删除此分支 — 本回合及其以下的所有内容`。
3. 阅读确认信息。它列出回合数量、会消失的转写文件，以及 Spinney 会终止的后台终端。点击 **删除分支**。

命令面板命令 `Spinney: 删除检出回合处的分支` 对检出的回合做同样的事。

Spinney 在两种情况下拒绝删除：

- 会话中有回合在运行：`智能体运行期间无法删除分支。请等该回合结束。`
- 分支中有子智能体在运行：`无法删除包含正在运行的子智能体的分支。请先终止它。`

删除后，检出移到该分支的父节点。删除是永久的。转写文件也会离开磁盘，因此 `search_transcripts` 再也找不到它们。

### 4.3 停止

**停止** 是一个动作，只有一个含义：停止该节点拥有的一切。

| 正在运行的内容 | 停止会做什么 |
|---|---|
| 该节点的回合 | 中止它。部分输出保留在卡片中。 |
| 它的子智能体 | 终止整批以及它的第 2 层子节点。 |
| 它的后台终端 | 终止进程树。 |
| 一条排队的完成通知 | 改为把该通知写入该节点的历史。模型会在你下一次提示时或用 **▶ 继续** 看到它。 |

停止只触及一个节点。其他分支和其他会话继续运行。

## 5. 会话与标签页

**会话** 视图列出每个会话，最近有变更的在前。每一行显示标题、一个状态图标，以及一行 `{0} 个节点 · <time>`。正在运行回合或后台任务的会话显示一个旋转指示器。

一个会话恰好拥有一个标签页。打开一个会话会聚焦它的标签页。它绝不会打开第二个。

| 操作 | 做法 |
|---|---|
| 新建会话 | 点击视图标题栏中的 **Spinney: 新建会话**。 |
| 打开一个会话 | 点击列表中的那一行。 |
| 重命名 | 右键点击该行，然后 `Spinney: 重命名会话…`。手动重命名会锁定标题。 |
| 自动重命名 | 右键点击该行，然后 `Spinney: 自动重命名会话`。这会去掉锁并立即重新生成标题。 |
| 复制会话 id | 右键点击该行，然后 `Spinney: 复制会话 ID`。 |
| 删除一个会话 | 把鼠标悬停在该行上，然后点击 **🗑**。 |
| 删除多个会话 | 用 `Ctrl`-点击或 `Shift`-点击选中这些行，然后点击任一选中行上的 **🗑**。Spinney 在一次确认之后删除整个选择。 |
| 清空对话 | 运行 `Spinney: 清除对话`。 |

打开 `spinney.autoSessionTitles` 时，Spinney 在第一个回合之后根据对话为会话命名一次。之后对话继续增长也不会再改名。重命名会停止自动命名。如果模型调用失败，标题退回为第一段提示词，Spinney 会在之后某一轮再试一次。

会话历史存放在扩展的会话数据文件夹中，是普通文件：每个会话一个文件夹，每个节点一个文件。

| 操作 | 结果 |
|---|---|
| 导出数据 | `Spinney: 导出会话数据` 把该文件夹复制到你指定的位置。已删除的会话与内部锁不会随之导出。 |
| 导入数据 | `Spinney: 导入会话数据` 把另一个文件夹中的会话并入当前窗口。已存在的会话不会被替换。 |
| 把数据放在同步盘 | 把 `spinney.dataDir` 设为该文件夹。下次重载窗口后生效。 |

| 事件 | 会发生什么 |
|---|---|
| 重新加载窗口，或重启 VS Code | 会话和打开的标签页都会回来。 |
| 关闭一个标签页 | 会话保留。只有标签页消失。正在运行的回合继续。 |
| 第二个窗口打开同一个文件夹 | 一个文件夹的会话由一个窗口拥有。另一个窗口显示相同的会话，你可以在那里浏览和阅读它们。它拒绝每一次变更：发送、继续、新建会话、删除、重命名和清空。消息为 `Another window owns this workspace’s sessions, so this window is read-only. Close that window (or use it) to continue here.` |
| 删除一个会话 | Spinney 移除历史、删除转写文件并终止后台终端。回合运行期间它会拒绝。 |
| 删除最后一个会话 | Spinney 新建一个空会话。 |
| 换一台电脑 | 在旧机运行 `Spinney: 导出会话数据`，在新机运行 `Spinney: 导入会话数据`。 |

## 6. 模型与服务商

**模型卡片**是一个可选模型。**服务商**是一个端点。一张卡片总是指定一个服务商。

用 **`Spinney: 打开模型卡片`** 打开模型卡片页面，或用聊天中模型下拉列表旁边的齿轮按钮。该页面把服务商画成根，把它们的卡片画成分支。选择一个节点可打开它的表单。

该页面把你的修改保存为草稿。它在标签页标题中显示 `* `，在状态条中显示 `有未保存的修改。`。**保存** 一次写入全部内容。**还原** 丢弃草稿。

Spinney 在页面中检查草稿，并在宿主中再次检查。被拒绝的保存不写入任何内容。

该页面保存在 `settings.json` 的 **Global** 作用域，因此这些卡片属于你的 VS Code 配置档案。其他每个 `spinney.*` 键都是窗口作用域。

### 6.1 服务商字段

| 字段 | 含义 |
|---|---|
| id | `spinney.providers` 中的键。它永不改变。id 为 `default` 的行会替换内置服务商。 |
| `name` | 显示名称。Spinney 在模型下拉分组、余额行和 API 密钥提示中显示它。 |
| `baseUrl` | API 根地址，例如 `https://api.deepseek.com`。请求发往 `POST <baseUrl>/chat/completions`。 |
| `balance` | Spinney 如何读取剩余额度。见下表。 |
| `sessionHeader` | Spinney 如何告诉端点一个请求属于哪段对话。`none` 不发送此类请求头。`opencode` 发送 `x-opencode-session`。 |
| `concurrency` | 可以针对此端点同时在途的请求数。`0` 表示不限。 |

| `balance` 值 | 请求 | 结果 |
|---|---|---|
| `none` | 无请求。 | 没有余额数字。这是新行的默认值。 |
| `deepseek` | `GET /user/balance` | 总额、赠送部分和充值部分。 |
| `openrouter` | `GET /credits` | 剩余额度，单位为 USD。 |
| `moonshot` | `GET /users/me/balance` | 可用余额，单位为 CNY。 |

省略 `balance` 的行按其主机来读取：`api.deepseek.com` 得到 `deepseek`，其他任何主机得到 `none`。

`sessionHeader` 有两个值。`none` 不发送请求头。`opencode` 发送 `x-opencode-session: ses_…`，OpenCode Console 网关要求该请求头。省略 `sessionHeader` 的行同样按其主机来读取：`opencode.ai` 得到 `opencode`，其他任何主机得到 `none`。Spinney 为每个上下文窗口发送一个值。新窗口或分叉会开始新的值。子智能体发送自己的值。

### 6.2 模型卡片字段

| 字段 | 含义 |
|---|---|
| id | 生成的 id。它永不改变，因此重命名是安全的。会话和转写保存该 id。 |
| `name` | 模型下拉列表中的标签。两张卡片不能同名。 |
| `providerId` | 该卡片对话的服务商。 |
| `oaiModel` | 进入请求的线路模型名称。在你设置它之前，新卡片无效。 |
| `contextWindow` | 卡片的 token 预算。`ctx` 读数用它做除数。它不是 API 的输出上限。 |
| `concurrency` | 该卡片可以同时在途的请求数。`0` 表示不限。卡片绝不会超过其服务商的限制。 |
| `vision.enabled` | 卡片是否接受图片。 |
| `vision.transport` | `deepseek` 把图片上传到 `POST /files` 并引用返回的 id。`openai` 把 `data:` URL 放进请求体。 |
| `searchProvider` | 由哪个引擎主导网络搜索。`builtin` 使用内置后端。`deepseek` 使用该卡片所属服务商的搜索 API。内置卡片 `deepseek-flash` 在没有设置该字段时使用 `deepseek`，即使你改过它的其他字段。你自己新建的卡片使用 `builtin`。见 19.1 节。 |
| `efforts` | 该卡片的思考级别，按下拉顺序排列。名称可自由填写。 |
| `defaultEffort` | 新会话开始时使用的级别。它必须是该卡片 `efforts` 之一。 |

Spinney 不做任何探测。上下文窗口、图片支持、传输方式和搜索引擎都是你的声明。错误的 `contextWindow` 会让 `ctx` 读数不准。

内置行无法删除。你可以编辑它们。页面始终显示内置服务商和内置 `deepseek-flash` 卡片。全新配置档案在 `settings.json` 中没有这些行。页面仍然显示这两行，第一次保存会把它们写入 `settings.json`。

### 6.3 选择模型

模型和推理力度属于节点，不属于标签页：

1. 一个回合保存它运行时使用的卡片和级别。
2. 后续回合使用最近的祖先节点的卡片和级别。
3. 新会话以 `spinney.model` 开始，或以内置的 `deepseek-flash` 卡片开始。

在下拉列表中的一次选择会更新实时配置，新节点会冻结该实时配置。继续一段已冻结对话的发送会保留冻结的配置（第 3.4 节）。检出会丢弃这次选择，下拉列表会跟随检出的节点。

模型、推理力度或回复语言的变更绝不会重写已冻结对话的配置。新值适用于下一个新节点。

会话中有任何回合运行时，这两个下拉列表都被禁用。

## 7. 推理力度

推理力度下拉列表包含当前卡片的级别。每张卡片拥有自己的列表。切换卡片时列表随之切换。

级别 `none` 很特殊。它根本不发送 `reasoning_effort`，系统提示词也去掉力度那一句。

Spinney 绝不发送卡片没有声明的级别。卡片不提供的级别会回退到该卡片的 `defaultEffort`，且不给任何消息。

## 8. 子智能体、会话与后台终端

### 8.1 子智能体

智能体用 `spawn_agents` 工具启动一个子智能体。每个子智能体并行运行自己的对话。它的卡片位于父卡片旁边，带有一个 `SUB` 徽标。

| 事项 | 细节 |
|---|---|
| 深度 | 两层。子智能体不能再启动更深的子智能体。 |
| 数量 | 同时 `spinney.maxConcurrentSubagents` 个第 1 层子智能体（默认 15）。多出的任务在队列中等待。 |
| 第二层 | 每个子智能体最多启动 `spinney.maxLevel2Subagents` 个子节点（默认 2）。 |
| 模式 | 可写的子智能体可以修改文件并运行命令。只读的子智能体只能读取。 |
| 卡片 | 徽标行显示深度、模型，以及 `可写` 或 `只读`。**✕** 按钮终止它。卡片还显示这次运行的用时。子智能体运行期间该数字会走动，运行结束后仍然保留在卡片上。 |
| 结果 | 子智能体结束时，Spinney 向父节点投递一条通知。该通知带有这次运行的用时。卡片显示 `Delivered`。 |
| 报告 | Spinney 在父回合的下一个工具边界投递该通知。父节点空闲时，Spinney 把该通知注入父节点。它绝不会新建节点。 |

一个子智能体批次等待的时间同样不超过 `spinney.subAgentSyncSeconds`（默认 300 秒）。批次到该时间仍在运行，`sync` 模式（默认）下的 `spawn_agents` 和 `send_agent_message` 就会返回智能体 id。所有摘要随后作为一条批次通知到达。

你不能在子智能体卡片中输入。要延续已结束的子智能体，请让父智能体去做。

按 **停止** 时，Spinney 终止该节点的整个子智能体子树。它把待投递的通知写入该节点的历史。被终止的子智能体绝不会自行恢复。

重启后，正在运行的子智能体显示为 `已终止`。

### 8.2 后台终端

后台终端在回合继续的同时保持一条长命令。智能体通过带 `run_type` 的 `exec_command` 启动一个后台终端。

一条命令在 `spinney.execForegroundSeconds`（默认 30 秒）之后仍在运行，就会自行转入后台。没有东西丢失，也没有东西被终止。工具的结果给出该任务的 id，智能体可以继续其他工作，或者结束本回合。

`run_type` 决定该调用是什么身份。它有三个取值。按任务的生命周期来选，不要按命令可能花多久来选。不确定时用默认值。

| 取值 | Spinney 启动什么 | 代价是什么 |
|---|---|---|
| `foreground` | 一开始不启动任何东西。命令在本回合内运行。超过 `spinney.execForegroundSeconds` 后，Spinney 把它转入后台。该取值是默认值。 | 命令及时结束时没有代价。转入后台之后与下一行相同。 |
| `background` | 立即在该节点上启动一个任务。 | 该任务结束前，该节点不能发送消息。任务结束时 Spinney 发送一条完成通知。 |
| `global` | 立即启动一个分离任务。该任务不锁定任何节点。 | 该节点保持空闲。该任务不发送通知，所以智能体只在主动查询时才知道它的结果。该会话中的任何节点都能读取或终止该任务。 |

任何任务都没有截止时间。任务一直运行到命令结束，或者直到 Spinney 或你终止它。没有 `timeout` 参数，也没有 `timeout_behavior` 参数。仍然传入其中一个的调用会得到错误，并且不会启动任何东西。

智能体用 `check_command` 读取任务。答案给出状态和到目前为止的输出。状态查询不会等待，所以智能体不得对正在运行的任务反复查询。智能体用 `wait_for_command` 等待：该工具最多等待它给出的秒数，任务一结束就返回。等待先结束时，智能体可以再次等待。智能体用 `kill_command` 结束任务。能运行命令的子智能体也拥有这三个工具。

智能体启动任务或把任务转入后台时，Spinney 会告诉它可以继续其他工作，或者结束本回合：任务结束时完成通知会到达。

智能体不会自己把进程放到后台，例如用 `&` 或 `Start-Process`。Spinney 无法跟踪这样的进程，你也不能从卡片上终止它。

卡片显示 `#<id>`、状态、已用时间、命令和最后几行输出。命令运行期间，已用时间会走动，命令结束后仍然保留在卡片上。命令的结果也会告诉智能体该命令花了多长时间。分离任务会显示 `global` 徽标：该徽标表示该任务绑定在当前 VS Code 窗口上、即发即忘，所以卡片从不等候智能体。

| 状态 | 含义 |
|---|---|
| `运行中` | 命令正在运行。**终止** 按钮是活动的。 |
| `待投递` | 命令已结束。通知在等待智能体。 |
| `退出码 {0}` | 命令的退出码。 |
| `已终止` | Spinney 或你终止了进程树。 |
| `已结束` | 记录的终点。 |

分离任务从不显示 `待投递`，因为它不发送通知。

后台任务属于启动它的节点。它不会锁定另一个分支或另一个会话。`#id` 是会话计数器，不是操作系统的 pid。

任务结束时，Spinney 用与投递子智能体通知相同的方式投递一条通知。之后卡片保留为记录，带有一个 `Delivered` 徽标。

Spinney 在以下情况下终止正在运行的任务：

- 你在拥有该任务的节点上按 **停止**。
- 你删除该分支或该会话，或者清空对话。会先弹出一个模态框询问。
- 你关闭窗口。

重启后，正在运行的任务显示为 `已中断`。卡片绝不会在并非活动时声称自己是活动的。

子智能体可以启动并管理自己的后台终端。只读子智能体完全不能运行命令。

### 8.3 会话与节点

智能体可以和其他会话协作。它有六个工具用于这件事。

| 工具 | 作用 |
|---|---|
| `create_session` | 新建一个会话，给它命名，并把第一条消息发到那里。调用立刻返回，因此智能体自己这一轮继续。新会话并行运行自己的回合。Spinney 不打开也不聚焦它的标签页。新会话出现在「会话」视图中。新会话的第一条消息拿到调用方剩下的回合数。 |
| `send_session_prompt` | 把一个提示词发到一个会话。提示词是一条用户消息，它会开始一个新回合。它落在该会话的活动节点上，也就是你发送时会落到的那个节点。你不用给节点 id。调用在回合开始后返回，不等回复。它返回一张收据。发出之后请结束你这一轮：回复会作为你节点上的新回合到来。一个会话在自己跑着回合时收不到回复。该节点正在运行回合，或仍拥有未完成的工作时，这条提示词被拒绝。拒绝信息会点名 `wait_for_session_idle` 和 `interrupt_session`。调用必须给出回合预算（`max_rounds`）。 |
| `wait_for_session_idle` | 等到一个会话可以接受提示词。默认 30 秒，最长 300 秒。会话一空出来，调用就返回。时间先到也是正常结果，不是错误。结果会指出占住该会话的节点和原因。 |
| `interrupt_session` | 结束某个会话中由智能体的提示词开始的工作。它停掉该回合、它的后台任务和它运行的子智能体。它停不了你开始的回合。它报告自己停了什么。 |
| `list_sessions` | 列出会话及其 id、标题、节点数，以及正在运行的节点数。查询词可以过滤列表。 |
| `list_nodes` | 列出一个会话的树。每一行给出真实状态：`running` 表示有正在运行的回合，`busy` 表示节点仍拥有未完成的工作，`checked out` 表示当前查看的节点。收到过提示词的节点显示 `from=` 和剩余的回合数。查询词可以过滤行。 |

新会话看不到创建它的那段对话。第一条消息必须包含新会话需要的全部内容，包括回执要送达的节点。工具调用本身不送达任何东西：发给调用方的消息是另一次调用，可以稍后发生。

这些工具只属于主智能体。子智能体不能创建会话，也不能向会话发送消息。

回合预算阻止两个会话在没有人的情况下互相回复。调用方每条消息给出 `max_rounds`。接收方可用的轮数少一轮。它不能增加这个数。`spinney.sessionMaxRounds` 是上限。轮数用尽的节点不能再发送。你亲手输入的消息会重新开始一份预算。

### 8.4 终端坞

终端坞显示本窗口的每个全局（global）终端。它在每个聊天标签页的右上角。你可以从任何标签页查看和控制任务，无论任务属于哪个会话。节点自己的后台任务不在终端坞里，它在节点旁的卡片上。

标题显示正在运行的任务数量，例如 `终端 · 1 个运行中`。点击标题可以收起或展开列表。没有任务时，终端坞不显示。每一行显示会话标题、任务编号、状态、已用时间、命令和最后几行输出。一行的信息与该任务的卡片相同。

| 行或按钮 | 操作 |
|---|---|
| 运行中的任务 | **终止** 按钮终止该任务的进程树。 |
| 已结束的任务 | **✕** 按钮把该行从终端坞中移除。 |
| **清除已结束的** | 把所有已结束的任务从终端坞中移除。 |

**✕** 和 **清除已结束的** 不会删除任务卡片。卡片留在它的节点旁边，保留状态和 `Delivered` 徽标。要删除卡片，请用卡片的删除按钮，或删除该分支。

Spinney 把移除记录保存在会话里。重新加载后，已移除的行不会再出现。

你不能把运行中的任务从终端坞移除。请先终止它，然后再移除它。

## 9. 图片

用 **附加图片** 按钮附加图片，或把图片粘贴到输入框。待处理的附件显示为小图片，带一个 **×** 按钮。

只有 `vision.enabled` 的卡片接受图片。Spinney 自带的 `deepseek-flash` 已开启图片支持。

| 情况 | 会发生什么 |
|---|---|
| 卡片不支持图片 | 附件被拒绝：`切换到支持图像的模型（{0}）即可附加图片。` |
| 没有卡片支持图片 | `没有配置支持图像的模型 — 请在某张模型卡片上启用视觉支持以附加图片。` |
| 你切换到不支持图片的卡片 | Spinney 隐藏历史中的图片。它保留数据，并在支持图片的卡片回来时恢复数据。 |
| 传输方式为 `deepseek` | Spinney 先上传图片。状态行随后显示 `正在上传图片…`。**停止** 会中止那次发送。 |
| 上传失败 | `无法上传：{0}。这些图片已被省略。` |

一张图片最大 64 MiB。格式为 JPEG、PNG、GIF 和 WebP。Spinney 从内容读取格式，而不是从文件名。

一张 4000 px 的图片和小图片花费相同。智能体用 `read_image` 工具读取图片。Spinney 在上传之前裁切图片并把它变小，所以模型看到的最长边是 1024 px。参数 `rect` 会把其中一块区域保留为原始细节。如果请求已经携带太多图片字节，工具会拒绝这张图片，并让智能体交给子智能体去看。

已上传的图片不能移到另一个服务商。`file_id` 只属于生成它的服务商。卡片显示 `[image hidden: it was uploaded to a provider that this model cannot read from]`。`openai` 传输没有这个问题。

## 10. 错误、重试与继续

### 10.1 自动重试

Spinney 最多重试一个请求 10 次。等待时间为 1 秒、2 秒、4 秒，依此类推，上限为 30 秒。

状态行显示 `模型调用失败（{0}/{1}）；{2} 后重试…`。第一个数字是失败的尝试次数。

Spinney 重试这些失败：

- 网络错误。
- HTTP `408`、`429` 或任何 `5xx`。
- 一个 `200` 应答，但正文为空。

Spinney 不重试这些失败：

- HTTP `400`、`401`、`403`、`404` 或 `422`。这些无法自行修复。
- 流中间的断点。这种重试会重复输出。Spinney 改为把整个请求再次发送（见下文）。
- 图片上传。
- 余额读取。

等待期间按 **停止** 会立即结束重试。

停滞的请求有边界。Spinney 为首字节等待 20 秒，为首块等待 20 秒，块之间等待 60 秒。停滞的请求显示 `思考中…`，且 `tok/s` 为 0。

上面这十次尝试属于一个请求。它们全部失败后，回合不会就此结束。Spinney 会自己把同一个完整请求再次发送，最多再发 3 次，整个回合在约 6 分钟之内。

智能体不会得知这些尝试。Spinney 原样发送当前的对话。如果回答已经开始，Spinney 会把写了一半的回答保留为模型的消息，并在它之后再次发送请求。没有任何文本会出现两次。

网络错误、停滞的流、HTTP `408`、HTTP `429` 和 `5xx` 会得到新的请求。拒绝会立即结束该回合。

Spinney 再次发送请求期间，卡片会显示一行标记，例如 `⟳ 静默重试 1/3`。随着尝试推进，Spinney 会改写这一行，所以工作日志只有一行，而不是每次尝试一行。智能体不会读到这一行。

状态行像以前一样报告失败的尝试和等待。

当所有尝试都失败时，回合仍会以错误结束，卡片保留它的按钮（第 10.2 节）。

### 10.2 卡片按钮

每张卡片最多带两个按钮之一。按钮取决于节点的状态。

| 节点状态 | 按钮 | 作用 |
|---|---|---|
| `已中断` | **▶ 继续** | 在同一张卡片中恢复该回合。部分输出保留。不会告知智能体任何内容。当 **停止** 在工具调用中途停止它时，智能体会得到一条简短的说明，指出那个调用，卡片会显示这条说明。 |
| `错误` | **↻ 重试** | 在同一张卡片中从停止处恢复该回合。该回合已完成的轮次会保留，所以智能体不会重复那部分工作。不会告知智能体任何内容。 |

卡片从不带有用于新上下文窗口的按钮。输入区带有这个入口，适用于每一次 epoch 变更（第 3.4 节和第 10.3 节）。

按钮承担这项工作。你不需要自己输入指令。**停止** 之后再输入新消息，行为与以前相同：你的消息会开始一个正常的回合（第 4.3 节）。

### 10.3 上下文窗口已满

当服务商用上下文长度错误应答时，上下文窗口就满了。请求还会携带其中的图片，形式是已上传的字节。服务商把这些字节的上限设为每个请求 200 MB。因为这个原因被拒绝，也算窗口已满。例如，消息为 `Total image size exceeds the limit: max 200 MB per request, got 203 MB`。Spinney 不会从 `ctx` 读数猜测限制。卡片显示一条 **⚠️** 消息。输入区显示 **压缩…**，并且 **发送** 被禁用。

在失败之前，Spinney 也会提供这个按钮。卡片的 `contextWindow` 用到约 90% 时，按钮就会显示。那时没有任何东西失败，所以点击是你自己的决定。此时普通发送仍然是普通发送。在 **发送** 上点右键，可以在任何时候、任何填充度下打开同一个问题。

1. 点击 **压缩…**。输入区把你的消息发送到新窗口。如果该节点仍拥有正在运行的工作，会先弹出一个模态框询问。它列出将停止的工作。
2. 回答 `Start a new context window?` 这个问题，选择 `Simple` 或 `Agentic`。10.4 节说明这两种答案。关闭对话框则什么也不发送，输入框保留你的文字。
3. Spinney 在该节点下方打开一张新卡片。边为虚线，标题为 `上下文窗口 {0}`，徽标为 `CTX`。由压缩节点产出的窗口，边为点线。

新窗口以系统提示词、一条 harness 消息和你的消息开始。harness 消息给出上一个窗口的记录文件、已停止的工作，以及上一个窗口的大小。选择 `Simple` 时，它还以上一个窗口的第一条请求、你的最后一次请求、该窗口改动过的文件，以及最后一次回答，用缩短的形式保存。选择 `Agentic` 时，它以压缩节点写下的交接开始，随后是你的最后一次请求，用你自己的话写出。附件无法跨越，因此该消息改为列出它们的名称。

旧分支仍然可用。你可以再次向它发送，或在那里按 **▶ 继续**，直到它再次溢出。

`CTX` 的工具提示为 `此节点开启新的上下文窗口；其上方分支不再发送给模型`。

两个不是故障的细节：

- 新卡片固定的用户消息就是你的消息。
- 无论显示语言是什么，harness 的文本都是英文。它还会告诉新智能体：收到的是交接，不是记忆。智能体必须说明某个事实来自交接，并且不得把某个命令或文件说成自己在新窗口里运行过或读过，除非确实做过。

### 10.4 两种交接

问题有两个答案。

- **Simple** 不额外花一次请求。新窗口被指向上一个窗口的记录，智能体在需要细节时读取那份记录。交接清单里包含上一个窗口的第一条请求、你的最后一次请求、该窗口改动过的文件，以及被停下的工作。
- **Agentic** 会先多跑一个回合。一个**压缩节点**（`CMP`）读取即将结束的那个窗口。它读磁盘上的记录、工作区，以及该窗口改动过的文件。它写出一份简短的简报：目标、你持续有效的要求、事实、改动、验证、死路，以及剩余计划。新窗口从这份简报开始。

压缩节点不能改动任何东西。它只能读文件、列目录、搜索文件和搜索转写。它的卡片没有输入框。它运行期间，卡片自带 Stop。两套设置不一致时，会再问一个问题：新窗口沿用哪一套设置继续。`沿用这个窗口的设置` 会继承这段对话已冻结的设置，也就是服务商已经缓存过的内容。`使用最新的设置` 会改为冻结当前的模型和推理力度，它的第一次请求会错过缓存。两边设置一致时，Spinney 不会问。

同一张卡片可以开多个窗口。每次尝试都是它下面的一条新分支，所以你可以两个都留着对比：例如一个 `Simple`、一个 `Agentic`。某次尝试还在跑时，等它结束再开下一个。

新窗口在压缩节点下方开始。窗口沿用它所继续的那个窗口的冻结设置，而不是压缩那一回合的设置。它的徽标是 `CTX`，边为点线。

你可以停止压缩节点。如果你停了它，或者它什么也没写，就不会打开新窗口，卡片保留它的继续按钮。新窗口一旦存在，这次压缩就结束了。要重做，请从它上面的窗口重新发起。

压缩产出的窗口没有删除按钮。请改为删除压缩节点。那会连同压缩回合、它产出的窗口，以及该窗口下方的一切一起删掉。

压缩节点是树里的普通卡片。点击它可以读到它做了什么。它显示自己的工具行。压缩节点的回答很长。在那张卡片上，回答在自己的框里滚动，卡片仍然显示它上面的步骤。

HARNESS 块只占一行：一个蓝色标签和文字的开头。点击这一行，可在小窗口里阅读整段文字，窗口自己滚动。再次点击可收起。窗口里按 Markdown 呈现这条消息：标题、列表和代码都按各自的样式显示。Spinney 在你打开窗口时才渲染这段文字。`[Harness: …]` 那种标题行不在窗口里：蓝色标签就是它。标签会写明它是哪一块：`压缩指令`、`交接摘要`、`上下文交接` 或 `harness 消息`。

所有键都以 `spinney.` 开头。打开设置 UI，或编辑 `settings.json`。

| 键 | 默认值 | 含义 |

| `spinney.sessionMaxRounds` | `16` | 两个会话之间一次往来的最大回合数。最小 1，最大 64。调用方每条提示词给出 `max_rounds`。这个数不能大于本设置。 |

| `spinney.streamAnimation` | `true` | 为进行中回合的文字和行加上动画。新字符淡入，新行淡入并向上移动。关闭后每个字符和每一行都立即绘制。操作系统的减少动态效果设置也会关闭动画。 |

| `spinney.autoSessionTitles` | `true` | 在第一个回合之后根据对话为会话命名一次。 |
| `spinney.saveSessionTranscripts` | `true` | 把每个已结束的回合以 JSONL 写入磁盘。 |
| `spinney.saveSubAgentTranscripts` | `true` | 把每个已结束的子智能体对话以 JSONL 写入磁盘。 |
| `spinney.subAgentTranscriptDir` | `""` | 转写文件的文件夹，相对于智能体根目录。为空表示扩展存储。 |
| `spinney.dataDir` | `""` | 存放会话的文件夹。为空表示扩展存储下的固定文件夹，且不以扩展 id 命名——重命名或重装都不会移动你的历史。填入你备份的文件夹即可把历史放在本机 profile 之外。下次重载窗口后生效。 |
| `spinney.diagnostics.log` | `true` | 为本窗口写诊断日志。其中只有耗时、计数与路径——不含你的对话。每一行都以时间戳结尾。命令开始时还会写一行，运行期间每 30 秒写一行心跳，结束时写一行。每个窗口一个文件，更旧的文件被删除，单个文件到 2 MiB 时轮转。 |
| `spinney.httpApi.enabled` | `false` | 打开本地 HTTP 控制平面。见第 14 节。 |
| `spinney.httpApi.port` | `0` | 该控制平面的端口。`0` 让系统选一个。 |

变更立即生效，只有一个例外：`AGENTS.md` 文件需要重新加载窗口（第 13 节）。

## 13. 给智能体的指令

Spinney 会把两个指令文件加入系统提示词。

| 文件 | 适用范围 |
|---|---|
| `~/.spinney/AGENTS.md` | 本机上的所有工作区。 |
| 工作区根目录中的 `AGENTS.md` | 当前打开的工作区。 |

全局文件放你希望处处生效的规则。工作区文件放项目的规则，例如测试命令或代码风格。Spinney 先放全局指令，再放工作区指令。两者冲突时，以工作区文件为准。

四个要知道的事实：

- Spinney 在扩展宿主启动时各读取一次。编辑不会到达正在运行的窗口。更改文件后请重新加载窗口。
- 运行 **`Spinney: 打开全局 AGENTS.md`** 可编辑全局文件。文件不存在时，该命令会创建它。
- 全局文件对每个工作区生效，对未打开文件夹的窗口也生效。
- 未打开文件夹时，Spinney 不读取工作区文件，因为没有工作区根目录。

运行 **`Spinney: 显示系统提示词`** 可读取模型收到的准确提示词。内容跟随当前模型卡片、推理力度、回复语言，以及该会话的两份指令快照。运行 **`Spinney: 显示请求载荷`** 可读取下一次请求的完整 JSON 请求体。

## 14. 隐私与数据

Spinney 不发送遥测。它只连接你配置的服务商端点。

一个请求携带你的消息、工具结果和图片。它还以用户代理的形式携带 Spinney 的名称和版本，以便服务商识别客户端。若服务商的行设置了 `sessionHeader`，请求还会携带上下文窗口的标识。余额读取会向服务商增加一个请求。图片根据卡片的传输方式，以上传方式或请求体内联方式发往服务商。若卡片为网络搜索选择了 `deepseek`，搜索查询也会发往该卡片的服务商；只有在该页面读不到任何文本时，才会把该页面的地址发过去（见 19.1 节）。

扩展不保存已上传图片字节的任何副本。

| 内容 | 位置 |
|---|---|
| 对话 | 文件，位于扩展的会话数据文件夹中：每个会话一个文件夹，每个节点一个文件。`spinney.dataDir` 可以改该文件夹。旧版本的状态数据库只是迁移来源。 |
| 转写 | JSONL 文件，每个已结束的回合一个，每个子智能体一个。文件夹：扩展存储，或 `spinney.subAgentTranscriptDir`。 |
| 大的工具结果 | `<agent root>/.spinney/tool-output/`。 |
| API 密钥 | VS Code 密钥存储，由操作系统加密。绝不在 `settings.json` 中。 |
| 设置 | `settings.json`。模型卡片页面写在 **Global** 作用域。 |

Spinney 不会向你的 `.gitignore` 写入任何内容。如果你不想让溢出的工具输出进入提交，请自己添加 `.spinney/` 文件夹。

卸载后对话仍留在磁盘上。它们位于扩展的数据文件夹中。第 15 节会移除它们。

### 14.1 HTTP 控制平面

控制平面默认关闭。它监听 `127.0.0.1`，并需要一个 bearer token。

它为外部控制程序而存在。`POST /continue` 让智能体运行一条来自调用方的指令。把这个端口当作你机器的信任边界。只有在你需要时才打开它。

控制平面打开时，Spinney 把端口和 token 写入 `<extension storage>/http/<instanceId>.json`。

## 15. 卸载与清除数据

1. 为每个服务商运行 **`Spinney: 清除 API 密钥`**，或接受密钥仍然保留。
2. 在扩展视图中卸载 Spinney。
3. 手动删除文件夹 `<extension storage>/de-yu.spinney`。它保存对话、转写、备份、诊断日志和控制平面文件。
4. 如果你运行过旧版本，再删除它的行。旧版本把对话保存在状态数据库中。键为 `DE-YU.spinney`：一行位于 `globalStorage/state.vscdb`，另外每个 `<workspaceStorage>/<hash>/state.vscdb` 中各有一行。当前版本把对话保存在文件中，所以第 3 步就会移除它们。

注意两种拼写：文件夹名是小写，而行键保留扩展 id 的大小写。

你指定到自己文件夹的文件不在这些步骤之内。检查 `spinney.dataDir`、`spinney.subAgentTranscriptDir` 和任何 `.spinney/` 文件夹。

## 16. 无文件夹模式

Spinney 在未打开任何文件夹的窗口中也能工作。

- 工具调用中的相对路径以扩展存储中的暂存文件夹 `<extension storage>/no-workspace` 为基准解析。智能体通过绝对路径访问你的真实文件。
- 会话位于配置档案中，而不是工作区中。该配置档案的每个无文件夹窗口都显示相同的会话。一次只用一个窗口。
- Spinney 读取全局 `AGENTS.md`，但不读取工作区 `AGENTS.md`，因为没有工作区根目录。
- 溢出的工具结果发往 `<scratch folder>/.spinney/tool-output/`。

在同一窗口中打开一个文件夹，或关闭一个文件夹，Spinney 会立即切换模式。

## 17. 故障排除

| 症状 | 原因与修复 |
|---|---|
| `No API key configured for this provider.` | 用 `Spinney: 设置 API 密钥` 设置密钥，或在模型卡片页面为具名服务商设置。 |
| 请求立即失败，没有重试 | `400`、`401`、`403`、`404` 或 `422`。阅读消息。常见原因是密钥错误和模型名称错误。 |
| 状态行重复 `retrying` | 网络故障、`429` 或 `5xx`。状态行无法区分死套接字和服务商错误。按 **停止** 结束等待。Spinney 会在回合结束前自己把整个请求再次发送，最多 3 次（第 10.1 节）。 |
| `思考中…` 且 `tok/s` 长时间为 0 | 流停滞。看门狗在 20 秒到 60 秒后结束它。 |
| `ctx N%` 看起来不对 | 它用**上一次**请求的提示 token 除以卡片的 `contextWindow`。检查卡片的值。 |
| 没有余额数字 | 服务商的 `balance` 值为 `none`，或读取失败。Spinney 只读取一次余额，且从不重试。 |
| 智能体忽略 `AGENTS.md` 中的新规则 | 重新加载窗口。Spinney 每次激活只读取该文件一次。 |
| 图片无法附加 | 当前卡片不支持图片。为卡片添加 `vision`，或切换到支持图片的卡片。 |
| 回合开始前要等待 | 并发闸门。状态行会说明等待原因。提高服务商或卡片上的 `concurrency`，或者等待。 |
| 模型下拉列表是灰色 | 本会话中有回合在运行。停止它或等待它。 |
| 视图停在旧卡片上 | 手动平移或缩放关闭了跟随模式。点击 **跟随活动节点**。 |
| 活动栏里没有 Spinney | 窗口处于受限模式。Spinney 不支持未受信任的工作区，所以 VS Code 保持禁用它。信任该文件夹，然后重新加载窗口。 |

**Spinney** 输出通道保存诊断信息。用 View → Output 打开它，然后在列表中选择 `Spinney`。它会说明显示语言、模型配置问题，以及布局和性能行。

运行 **`Spinney: 显示系统提示词`** 查看准确提示词，运行 **`Spinney: 显示用户手册`** 重新打开本手册。


## 18. 上报卡顿或异常

Spinney 为每个窗口保留一份诊断日志。其中只有耗时、计数与路径——不含你输入的内容，也不含 API 密钥。

日志的每一行都以时间戳结尾，例如 ` | at=2026-09-21T04:14:48.123Z`。日志还会在命令开始时写一行、命令运行期间每 30 秒写一行心跳，并在命令结束时写一行。因此，卡住的命令事后能在日志中看到。日志也会记录后台任务的预算：Spinney 登记该任务时写一行（`bg register … budget=…`），预算用尽时再写一行（`bg expire …`）。

| 步骤 | 做法 |
|---|---|
| 1 | 复现问题。 |
| 2 | 运行 `Spinney: 打开诊断日志`，然后点 **在资源管理器中显示**。 |
| 3 | 把那一份文件发给支持你的人。 |

从输出面板复制的文字不是同一份文件：它没有文件头那一行，而该行会写明构建、进程与窗口的启动时间。

把 `spinney.diagnostics.log` 设为 `false` 可以停掉它。

Spinney 没有启动的进程可能残留。当一条命令把工作交给另一个程序时就会发生这种情况，例如编辑器、构建服务器或测试桥接程序。该程序的子进程在 Spinney 的进程树之外。**停止** 无法触及它，它的输出也永远回不来。Spinney 无法替你找到这样的进程。请使用任务管理器，或在 PowerShell 中运行以下命令：

```powershell
Get-CimInstance Win32_Process -Filter "name like '<program>%'" | Where-Object { $_.CreationDate -lt (Get-Date).AddHours(-2) } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

把 `<program>` 替换为残留程序的名称。该筛选条件匹配启动超过两小时的进程。

## 19. 网络搜索

Agent 可以搜索网络，并读取一个页面。内置后端不需要 API 密钥，也不需要任何设置。

| 工具 | 作用 |
|---|---|
| `web_search` | 把查询发给一组搜索后端，返回编号的结果列表：标题、网址和摘要。 |
| `web_fetch` | 读取一个网址，返回该页面的文本。HTML 页面会转换成 Markdown。 |

搜索后端是内置的。Spinney 按此顺序尝试：Bing (RSS)、360、百度、搜狗、Bing (HTML)、Hacker News、StackExchange、GitHub。结果里写明由哪个后端作答，以及其余后端各自的结果。

两条规则让搜索保持可用：

- 后端返回验证码或验证页面时，Spinney 会标记该后端，并在一段时间内跳过它；重复失败后跳过的更久。
- 网络不同，可用的后端也不同。部分地域无法访问 DuckDuckGo、Google、Mojeek 和 Wikipedia；另一些地域访问百度、搜狗和 360 时会遇到验证码。

搜索没有结果时，运行 **`Spinney: 测试网络搜索后端`**。Spinney 会向每个后端发送一个测试查询，并打开一张表，列出各自的结果、耗时和命中数。该命令只做测量，不修改任何设置。

`web_fetch` 会跟随一次跳转，最多读取 2 MB，并使用页面自身的字符集。它不执行 JavaScript。由浏览器动态生成的页面只会返回很少的文本，结果中会说明这一点。`web_fetch` 会拒绝私有地址，例如 `localhost` 和 `127.0.0.1`。

页面的文本不是对 Spinney 的命令。Spinney 把它视为陌生人的信息。如果页面试图对 Spinney 下达指令，Spinney 会向你报告。

### 19.1 通过服务商搜索

模型卡可以让自己的服务商用它的搜索 API 作为搜索的首选。该字段是 `searchProvider`。

- `builtin` 是你新建卡片的默认值。Spinney 只使用内置后端，不会向任何搜索 API 发送请求。
- `deepseek` 把 DeepSeek 搜索 API 作为第一个后端，内置后端仍然作为兜底。这时每条结果都带上更长的页面摘要、发布日期和评分。

内置的 `deepseek-flash` 卡片设为 `deepseek`。你不需要再设一次：即使你改过这张卡的其他字段，搜索仍然走 DeepSeek 搜索 API。其他卡片一律从 `builtin` 开始，留空该字段时也保持 `builtin`。

请求发往该卡片所属服务商的地址，该服务商的密钥就是令牌。如果搜索必须使用另一个令牌，请使用模型卡页面上的**搜索令牌**字段。该字段是全部卡片共用的一个令牌，页面上会写明请求发往哪个地址。留空则表示 Spinney 使用服务商的密钥。

服务商按每一次搜索请求计费。一次 `web_search` 调用就是一个请求，结果条数不影响价格。服务商还限制每个账号每秒的请求数。Spinney 会拉开请求间隔以留在限制之内。

有三种答复需要你来处理，重试没有用：令牌被拒、账号余额不足、服务商不提供该搜索地址。Spinney 各用一句话说明，并在几小时内不再使用该 API。

卡片是 `builtin` 时一切不变：工具不需要密钥，也没有查询会发到搜索 API。设为 `deepseek` 时，`web_fetch` 可以把页面地址发给该 API。它只在本地读不到该页面任何文本时才这样做，并且绝不会发送私有地址。

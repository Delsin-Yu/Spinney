# Spinney 用户手册

Spinney 是一个 VS Code 扩展。它把智能体放进一个编辑器标签页，并把对话保存成一棵可以分支的树。

Version: 0.0.2.

## 1. 安装与首次运行

1. 从 Visual Studio Marketplace 安装 **Spinney**。
2. 在 Activity Bar 中打开 **Spinney** 容器。它包含 **会话** 视图。
3. 点击视图标题栏中的 **Spinney: 新建会话**。一个标签页打开，标题为 `智能体聊天树 — 新会话`。
4. 设置 API 密钥（第 2 节）。然后在底部的输入框中写下第一条消息，并按 **Enter**。

`Shift+Enter` 新起一行。`Enter` 发送。

Spinney 在打开文件夹和未打开文件夹时都能工作。见第 16 节。

全新配置档案运行内置模型卡片 `deepseek-flash`。你可以更改它（第 6 节）。

## 2. 设置 API 密钥

Spinney 把密钥保存在 VS Code 密钥存储中，绝不保存在 `settings.json` 中。

1. 用 `Ctrl+Shift+P` 打开命令面板。
2. 运行 **`Spinney: 设置 API 密钥`**。
3. 在提示处粘贴密钥并确认。

VS Code 用 `Spinney：API 密钥已保存。` 确认。密钥立即生效。你不需要重新加载窗口。

运行 **`Spinney: 清除 API 密钥`** 可清除密钥。

两条特殊规则：

- 内置服务商也接受 `DEEPSEEK_API_KEY` 环境变量。只有在没有已保存的密钥时，Spinney 才使用该变量。
- 有多个服务商时，请在模型卡片页面（第 6 节）中、在该服务商那一行里设置每个密钥。

没有密钥时，每个请求都会失败，并显示 `No API key configured for this provider.`。Spinney 每个窗口显示一次 `设置 API 密钥` 按钮。

## 3. 聊天窗口

树中每个回合有一张卡片。新回合放在它所回答的那个回合下方。输入区就是输入停靠区。它位于你检出的那张卡片内部。

### 3.1 输入区

| 控件 | 作用 |
|---|---|
| 输入框 | 保存你的消息。`Enter` 发送，`Shift+Enter` 换行。 |
| **发送** | 发送消息并开始一个回合。配置发生变化时，Spinney 会标记这个按钮（第 3.4 节）。 |
| **停止** | 在检出的节点结束该回合。它也会终止该节点的后台终端和子智能体。没有任何内容继续。工具提示为 `停止这一轮` 或 `停止这个节点：终止它的后台任务与子代理（不会给模型发送任何内容）`。 |
| 提示词片段 | 打开一个预写指令菜单。点击会把文本插入输入框。不会发送任何内容。Spinney 自带 `Plan` 和 `Implement Parallel`。用 `spinney.promptSections`（第 11 节）添加你自己的行。 |
| **附加图片** | 打开文件选择器。你也可以把图片粘贴到输入框。见第 9 节。 |
| 模型下拉列表 | 为新节点选择模型卡片。继续这段对话的发送会先询问（第 3.4 节）。列表按服务商对卡片分组。 |
| 齿轮按钮 | 打开模型卡片页面。工具提示为 `管理模型卡片…`。 |
| 推理力度下拉列表 | 选择推理级别。该列表即当前卡片的列表。 |

**发送** 和 **停止** 是同一个按钮，有两种含义。当检出的节点正在运行一个回合，或该节点仍拥有未完成的工作时，按钮显示 **停止**。

当后台终端或一批子智能体在运行，或有完成通知在等待该节点时，该节点就拥有未完成的工作。你不能向这样的节点发送。没有队列。请先按 **停止**，或从另一个节点发送。

另一个分支或另一个会话可以同时运行。它不会阻塞这个输入区。

子智能体卡片没有输入区。它的分支是只读的，横幅显示 `子智能体分支（只读）— 由主智能体通过 spawn_agents / send_agent_message 驱动`。

### 3.2 树的工具栏与手势

工具栏有两个按钮：

- **跟随活动节点**（`⦿`）。视图让正在流式输出的节点保持在屏幕上。
- **适应视图大小**（`⤢`）。

| 手势 | 结果 |
|---|---|
| 滚轮 | 滚动视图。 |
| `Ctrl`+滚轮 | 缩放。 |
| `Shift`+滚轮 | 横向平移。 |
| 中键拖动 | 平移。 |
| 按住右键 | 朝指针方向平移。 |
| 拖动卡片的右下角 | 调整该卡片的大小。 |
| 右键点击卡片标题 | 打开卡片菜单。它包含 `复制节点 ID`。 |

手动平移或缩放会关闭那个按钮。

每个卡片标题都带有回合标题、一个状态标签和一个 **🗑** 按钮。该按钮删除该回合处的分支（第 4 节）。

卡片主体从上到下有三个部分。

第一部分保存你的消息。Spinney 始终显示这一部分，且从不折叠它。Spinney 以 Markdown 呈现这一部分。

第二部分是工作日志。它保存推理块、工具卡片、通知、后台任务通知、`HARNESS` 块，以及模型在工具调用之前写下的文本。工作日志会滚动。只有它带有绿色锁定圆点。该圆点控制自动滚动。正在进行的回合开始时为锁定状态。当回合完成时，工作日志会自动折叠成一个单行标题。该标题带有一个箭头和一个标签。标签显示为 `工作日志 · 3 个步骤`。该数字是工具卡片的数量。没有工具卡片时，标签只显示 `工作日志`。点击该标题可再次展开工作日志。你点击过一次的标题会保持你留下的状态。自动折叠绝不会推翻你的点击。锁定圆点遵循同样的规则。当你松开某张卡片的锁定圆点时，自动折叠不再折叠或展开这张卡片的工作日志。回合再次运行时，工作日志会自动展开。卡片没有回答可显示时，工作日志保持展开。把 `spinney.foldWork` 设为 `false` 可关闭自动折叠（第 11 节）。工作日志中的块保持各自的折叠行为（见下方以及第 11 节中的 `spinney.foldThinking` 和 `spinney.foldToolCalls`）。

第三部分是回答。它保存模型的最终消息。Spinney 把它显示在卡片底部，以 Markdown 呈现它，且从不折叠它。回答不带锁定圆点。只有当回合静止、且工作日志的最后一项是模型的消息时，Spinney 才显示回答。工作日志中出现更新的项时，回答就消失，例如后台任务、上报结果的子智能体、来自 **▶ 继续** 或 **↻ 重试** 的 `HARNESS` 块，或一次新的工具调用。此时那条消息又回到工作日志中。被中断回合的文本会作为回答显示。出错回合的文本不会作为回答显示。错误留在工作日志中。

当卡片显示回答、且工作日志保持展开时，回答优先，且只有回答的高度会使卡片变高。工作日志保留约 360 像素的条带，并在这条条带内滚动。拖动卡片的右下角可以让这条条带更高。回合运行期间还没有回答，卡片保持同样的条带高度，不会随着每次工具调用而变高。回答位于分隔线下方、属于它自己的表面上。

卡片现在最高可达 1200 像素。此前的上限是 600 像素。拖动卡片的右下角仍可调整它的大小。

按 `Ctrl+Alt+D` 把布局诊断写入输出通道。

### 3.3 状态行

输入框下方那一行显示会话的状态。

| 项目 | 含义 |
|---|---|
| 状态圆点 | 会话空闲时为暗色。有任何内容流式输出时呈琥珀色并脉动。 |
| 状态行 | `就绪`、`思考中…`、`正在上传图片…`、`正在停止…`、`已中断`、`错误`，或一条重试消息（第 10 节）。 |
| `ctx N%` | 上下文窗口用量。它用**上一次**请求的提示 token 除以卡片的 `contextWindow`。它是一个读数，不是限制。它可能出错。 |
| `bal …` | 正在应答的服务商的余额。`bal –` 表示不存在数字，例如在余额方言为 `none` 的服务商上。Spinney 只读取一次余额，且从不重试。 |
| `tok/s` | 输出速度。它是本地估算，不是服务商的计数。 |

每条回答和每张工具卡片都带有自己的 token 行：`tokens {0}（提示 {1} + 补全 {2}）· 缓存命中 {3} / 未命中 {4}`。

工具卡片保存调用、参数和结果。每张工具卡片显示这次调用的用时，调用结束后该数字仍然保留。一个 `HARNESS` 块保存 harness 发给模型的准确文本。推理块、工具卡片和 `HARNESS` 块都位于工作日志中。点击块标题可折叠或展开它。`spinney.foldThinking` 和 `spinney.foldToolCalls` 设置这些块的静止状态（第 11 节）。

有意保持英文的代码：`SUB`、`BG`、`CTX`、`HARNESS`、`Delivered`。

### 3.4 冻结的配置与多棵树

对话冻结在它开始时使用的配置上。该配置包含模型卡片、推理级别、回复语言，以及随扩展发布的系统提示词。一次普通的发送始终使用该冻结的配置。

选择另一张模型卡片、另一个推理级别或另一种回复语言，会让实时配置与冻结的配置不同。此时输入区会同时显示这两种配置，各占一行：

- `Sending with: {0}`。一次发送真正使用的配置。
- `New setup: {0}`。新节点将冻结的配置。

其中的值包含卡片、推理级别和回复语言。例如：`Sending with: deepseek-flash · medium · English`。

配置发生变更之前，Spinney 只问一个问题。问题是 `Continue with current setup` 或 `Continue with latest setup`。它出现在三种情况下：

- 更改模型下拉列表、推理力度下拉列表或 `spinney.replyLanguage`（第 11 节）。Spinney 会标记 **发送** 按钮。工具提示为 `Send will ask before using the old setup (the one this node froze)`。
- harness 侧发生变化：随扩展发布的系统提示词、工作区 `AGENTS.md`、工具集或端点。Spinney 会在提示词片段旁新增一个提示项。该项带有 `⧉` 符号，工具提示为 `Continue with the latest setup (forks this tree and sends there)`。点击它会打开同一个问题。
- 在新的上下文窗口中继续（第 10.3 节）。空上下文让最新配置不付出代价，所以那里也会问一次。

| 回答 | 会发生什么 |
|---|---|
| `Continue with current setup` | 发送使用冻结的配置。Spinney 丢弃你的选择。模型下拉列表和推理力度下拉列表重新显示冻结的值。 |
| `Continue with latest setup` | Spinney 把这棵树复制成一棵新树。新树以最新配置开始。旧树保留它自己的配置，以及它的提示词缓存。 |

按 `Escape`，或点击关闭按钮，即可关闭这个问题。被关闭的问题不发送任何内容，Spinney 会把你输入的文字留在输入框中。

一个会话可以容纳多棵树。Spinney 把新树放在当前树旁边。视图并排显示这些树，并把视图移到新树，每棵树都可以交互。检出你想继续的那棵树中的节点，然后发送。

### 3.5 重新加载聊天视图

聊天标签页可能显示对话的旧画面。例如某个卡片不再变化，或只显示树的一部分。对话是正确的，正在运行的回合也会继续。

运行 **`Spinney: 重新加载聊天视图`**，从会话的状态重新构建该标签页。当标签页显示冻结的画面，或某个卡片不再变化时，使用此命令。

该命令不会改变对话。它不会停止正在运行的回合。没有打开的聊天标签页时，Spinney 会回答 `Spinney：此窗口没有打开的聊天标签页。`

## 4. 分支

### 4.1 从回合创建分支

1. 点击你想从中分支的回合标题。卡片展开，输入区移入其中。
2. 写新消息。当该回合已经有子节点时，横幅显示 `⤷ 从 {0} 分支 — 你的回复将开启一个新分支`。
3. 按 **Enter** 或点击 **发送**。

新回合成为同级分支。Spinney 不删除任何内容。旧的那条线在树中保留为变暗的单行卡片。点一次就能把它调回来。

检出没有代价。你可以在一个回合流式输出的同时检出另一个回合。检出移动的是视图，不是正在运行的回合。

### 4.2 删除分支

1. 把鼠标悬停在开启该分支的回合标题上。
2. 点击 **🗑**。工具提示为 `删除此分支 — 本回合及其以下的所有内容`。
3. 阅读确认信息。它列出回合数量、会消失的转写文件，以及 Spinney 会终止的后台终端。点击 **删除分支**。

命令面板命令 `Spinney: 删除检出回合处的分支` 对检出的回合做同样的事。

Spinney 在两种情况下拒绝删除：

- 会话中有回合在运行：`智能体运行期间无法删除分支。请等该回合结束。`
- 分支中有子智能体在运行：`无法删除包含正在运行的子智能体的分支。请先终止它。`

删除后，检出移到该分支的父节点。删除是永久的。转写文件也会离开磁盘，因此 `search_transcripts` 再也找不到它们。

### 4.3 停止

**停止** 是一个动作，只有一个含义：停止该节点拥有的一切。

| 正在运行的内容 | 停止会做什么 |
|---|---|
| 该节点的回合 | 中止它。部分输出保留在卡片中。 |
| 它的子智能体 | 终止整批以及它的第 2 层子节点。 |
| 它的后台终端 | 终止进程树。 |
| 一条排队的完成通知 | 改为把该通知写入该节点的历史。模型会在你下一次提示时或用 **▶ 继续** 看到它。 |

停止只触及一个节点。其他分支和其他会话继续运行。

## 5. 会话与标签页

**会话** 视图列出每个会话，最近有变更的在前。每一行显示标题、一个状态图标，以及一行 `{0} 个节点 · <time>`。正在运行回合或后台任务的会话显示一个旋转指示器。

一个会话恰好拥有一个标签页。打开一个会话会聚焦它的标签页。它绝不会打开第二个。

| 操作 | 做法 |
|---|---|
| 新建会话 | 点击视图标题栏中的 **Spinney: 新建会话**。 |
| 打开一个会话 | 点击列表中的那一行。 |
| 重命名 | 右键点击该行，然后 `Spinney: 重命名会话…`。手动重命名会锁定标题。 |
| 自动重命名 | 右键点击该行，然后 `Spinney: 自动重命名会话`。这会去掉锁并立即重新生成标题。 |
| 复制会话 id | 右键点击该行，然后 `Spinney: 复制会话 ID`。 |
| 删除一个会话 | 把鼠标悬停在该行上，然后点击 **🗑**。 |
| 删除多个会话 | 用 `Ctrl`-点击或 `Shift`-点击选中这些行，然后点击任一选中行上的 **🗑**。Spinney 在一次确认之后删除整个选择。 |
| 清空对话 | 运行 `Spinney: 清除对话`。 |

打开 `spinney.autoSessionTitles` 时，Spinney 在第一个回合之后根据对话为会话命名，之后对话增长时再次命名。两次命名之间的等待至少为两分钟。重命名会停止自动命名。

会话历史存放在扩展的会话数据文件夹中，是普通文件：每个会话一个文件夹，每个节点一个文件。

| 操作 | 结果 |
|---|---|
| 导出数据 | `Spinney: 导出会话数据` 把该文件夹复制到你指定的位置。已删除的会话与内部锁不会随之导出。 |
| 导入数据 | `Spinney: 导入会话数据` 把另一个文件夹中的会话并入当前窗口。已存在的会话不会被替换。 |
| 把数据放在同步盘 | 把 `spinney.dataDir` 设为该文件夹。下次重载窗口后生效。 |

| 事件 | 会发生什么 |
|---|---|
| 重新加载窗口，或重启 VS Code | 会话和打开的标签页都会回来。 |
| 关闭一个标签页 | 会话保留。只有标签页消失。正在运行的回合继续。 |
| 第二个窗口打开同一个文件夹 | 一个文件夹的会话由一个窗口拥有。另一个窗口显示相同的会话，你可以在那里浏览和阅读它们。它拒绝每一次变更：发送、继续、新建会话、删除、重命名和清空。消息为 `Another window owns this workspace’s sessions, so this window is read-only. Close that window (or use it) to continue here.` |
| 删除一个会话 | Spinney 移除历史、删除转写文件并终止后台终端。回合运行期间它会拒绝。 |
| 删除最后一个会话 | Spinney 新建一个空会话。 |
| 换一台电脑 | 在旧机运行 `Spinney: 导出会话数据`，在新机运行 `Spinney: 导入会话数据`。 |

## 6. 模型与服务商

**模型卡片**是一个可选模型。**服务商**是一个端点。一张卡片总是指定一个服务商。

用 **`Spinney: 打开模型卡片`** 打开模型卡片页面，或用聊天中模型下拉列表旁边的齿轮按钮。该页面把服务商画成根，把它们的卡片画成分支。选择一个节点可打开它的表单。

该页面把你的修改保存为草稿。它在标签页标题中显示 `* `，在状态条中显示 `有未保存的修改。`。**保存** 一次写入全部内容。**还原** 丢弃草稿。

Spinney 在页面中检查草稿，并在宿主中再次检查。被拒绝的保存不写入任何内容。

该页面保存在 `settings.json` 的 **Global** 作用域，因此这些卡片属于你的 VS Code 配置档案。其他每个 `spinney.*` 键都是窗口作用域。

### 6.1 服务商字段

| 字段 | 含义 |
|---|---|
| id | `spinney.providers` 中的键。它永不改变。id 为 `default` 的行会替换内置服务商。 |
| `name` | 显示名称。Spinney 在模型下拉分组、余额行和 API 密钥提示中显示它。 |
| `baseUrl` | API 根地址，例如 `https://api.deepseek.com`。请求发往 `POST <baseUrl>/chat/completions`。 |
| `balance` | Spinney 如何读取剩余额度。见下表。 |
| `concurrency` | 可以针对此端点同时在途的请求数。`0` 表示不限。 |

| `balance` 值 | 请求 | 结果 |
|---|---|---|
| `none` | 无请求。 | 没有余额数字。这是新行的默认值。 |
| `deepseek` | `GET /user/balance` | 总额、赠送部分和充值部分。 |
| `openrouter` | `GET /credits` | 剩余额度，单位为 USD。 |
| `moonshot` | `GET /users/me/balance` | 可用余额，单位为 CNY。 |

省略 `balance` 的行按其主机来读取：`api.deepseek.com` 得到 `deepseek`，其他任何主机得到 `none`。

### 6.2 模型卡片字段

| 字段 | 含义 |
|---|---|
| id | 生成的 id。它永不改变，因此重命名是安全的。会话和转写保存该 id。 |
| `name` | 模型下拉列表中的标签。两张卡片不能同名。 |
| `providerId` | 该卡片对话的服务商。 |
| `oaiModel` | 进入请求的线路模型名称。在你设置它之前，新卡片无效。 |
| `contextWindow` | 卡片的 token 预算。`ctx` 读数用它做除数。它不是 API 的输出上限。 |
| `concurrency` | 该卡片可以同时在途的请求数。`0` 表示不限。卡片绝不会超过其服务商的限制。 |
| `vision.enabled` | 卡片是否接受图片。 |
| `vision.transport` | `deepseek` 把图片上传到 `POST /files` 并引用返回的 id。`openai` 把 `data:` URL 放进请求体。 |
| `efforts` | 该卡片的思考级别，按下拉顺序排列。名称可自由填写。 |
| `defaultEffort` | 新会话开始时使用的级别。它必须是该卡片 `efforts` 之一。 |

Spinney 不做任何探测。上下文窗口、图片支持和传输方式都是你的声明。错误的 `contextWindow` 会让 `ctx` 读数不准。

内置行无法删除。你可以编辑它们。

### 6.3 选择模型

模型和推理力度属于节点，不属于标签页：

1. 一个回合保存它运行时使用的卡片和级别。
2. 后续回合使用最近的祖先节点的卡片和级别。
3. 新会话以 `spinney.model` 开始，或以内置的 `deepseek-flash` 卡片开始。

在下拉列表中的一次选择会更新实时配置，新节点会冻结该实时配置。继续一段已冻结对话的发送会保留冻结的配置，并先询问（第 3.4 节）。检出会丢弃这次选择，下拉列表会跟随检出的节点。

模型、推理力度或回复语言的变更绝不会重写已冻结对话的配置。新值适用于下一个新节点。

会话中有任何回合运行时，这两个下拉列表都被禁用。

## 7. 推理力度

推理力度下拉列表包含当前卡片的级别。每张卡片拥有自己的列表。切换卡片时列表随之切换。

级别 `none` 很特殊。它根本不发送 `reasoning_effort`，系统提示词也去掉力度那一句。

Spinney 绝不发送卡片没有声明的级别。卡片不提供的级别会回退到该卡片的 `defaultEffort`，且不给任何消息。

## 8. 子智能体与后台终端

### 8.1 子智能体

智能体用 `spawn_agents` 工具启动一个子智能体。每个子智能体并行运行自己的对话。它的卡片位于父卡片旁边，带有一个 `SUB` 徽标。

| 事项 | 细节 |
|---|---|
| 深度 | 两层。子智能体不能再启动更深的子智能体。 |
| 数量 | 同时 `spinney.maxConcurrentSubagents` 个第 1 层子智能体（默认 15）。多出的任务在队列中等待。 |
| 第二层 | 每个子智能体最多启动 `spinney.maxLevel2Subagents` 个子节点（默认 2）。 |
| 模式 | 可写的子智能体可以修改文件并运行命令。只读的子智能体只能读取。 |
| 卡片 | 徽标行显示深度、模型，以及 `可写` 或 `只读`。**✕** 按钮终止它。卡片还显示这次运行的用时。子智能体运行期间该数字会走动，运行结束后仍然保留在卡片上。 |
| 结果 | 子智能体结束时，Spinney 向父节点投递一条通知。该通知带有这次运行的用时。卡片显示 `Delivered`。 |
| 报告 | Spinney 在父回合的下一个工具边界投递该通知。父节点空闲时，Spinney 把该通知注入父节点。它绝不会新建节点。 |

一个子智能体批次等待的时间同样不超过 `spinney.commandMaxForegroundDuration`。批次在该上限时仍在运行，`sync` 模式（默认）下的 `spawn_agents` 和 `send_agent_message` 就会返回智能体 id。所有摘要随后作为一条批次通知到达。

你不能在子智能体卡片中输入。要延续已结束的子智能体，请让父智能体去做。

按 **停止** 时，Spinney 终止该节点的整个子智能体子树。它把待投递的通知写入该节点的历史。被终止的子智能体绝不会自行恢复。

重启后，正在运行的子智能体显示为 `已终止`。

### 8.2 后台终端

后台终端在回合继续的同时保持一条长命令。智能体通过带 `timeout_behavior` 的 `exec_command` 启动一个后台终端。

任何操作占用一个回合的时间都不会超过 `spinney.commandMaxForegroundDuration`（300 秒，即 5 分钟）。`exec_command` 的 `timeout` 是命令的全部预算：前台时间加后台时间，没有上限。`timeout` 长于该上限时，不会启动任何东西，调用先被拒绝，除非它同时请求一个后台取值。

`timeout_behavior` 决定该调用是什么身份。它有四个取值：

| 取值 | Spinney 启动什么 | 代价是什么 |
|---|---|---|
| `stop_when_timeout` | 不启动任何东西。命令达到超时时间时仍在运行，Spinney 就终止它。该取值是默认值。 | 没有代价。 |
| `background_when_timeout` | 在该节点上启动一个任务。命令先在前台运行，最多到 5 分钟上限，随后 Spinney 把它转入后台。预算的剩余部分就是该任务的预算。该调用必须传入 `timeout`。 | 该任务结束前，该节点不能发送消息。任务结束时 Spinney 发送一条完成通知。 |
| `start_in_background` | 立即在该节点上启动一个任务。全部预算就是该任务的截止时间。该调用必须传入 `timeout`。 | 与上一行相同。 |
| `start_detached` | 立即启动一个分离任务。该任务不锁定任何节点。`timeout` 可以省略。 | 该节点保持空闲，并且该任务不发送通知，所以智能体只在主动查询时才知道它的结果。该会话中的任何节点都能读取或终止该任务。 |

预算用尽时，Spinney 终止该任务。`background_when_timeout` 和 `start_in_background` 都需要 `timeout`：不传 `timeout` 时，Spinney 不会启动任何东西，调用先被拒绝。没有截止时间的任务会一直占用它的节点，所以那样的任务属于 `start_detached`。拒绝消息会指出调用请求的取值，说明没有启动任何东西，并给出两条出路：传入 `timeout`，或者改用 `start_detached`。只有 `start_detached` 可以没有截止时间，因为它不锁定任何节点。`join_background` 同样不得让一个回合超过该上限：只要该任务的剩余预算还多于该上限，或者根本没有截止时间，join 就会被拒绝，并告知智能体结束本回合，完成通知随后才会到达。Spinney 也会拒绝分离任务的 join：该任务没有截止时间，也不发送通知，所以没有任何可等待的东西。智能体用 `check_background_terminal` 读取分离任务，用 `kill_background` 结束它。`check_background_terminal` 和 `kill_background` 对每个任务都可用。

智能体不会自己把进程放到后台，例如用 `&` 或 `Start-Process`。Spinney 无法跟踪这样的进程，你也不能从卡片上终止它。

卡片显示 `#<id>`、状态、已用时间、命令和最后几行输出。命令运行期间，已用时间会走动，命令结束后仍然保留在卡片上。命令的结果也会告诉智能体该命令花了多长时间。分离任务会显示 `shared` 徽标：该徽标表示该任务即发即忘，所以卡片从不等候智能体。

| 状态 | 含义 |
|---|---|
| `运行中` | 命令正在运行。**终止** 按钮是活动的。 |
| `待投递` | 命令已结束。通知在等待智能体。 |
| `退出码 {0}` | 命令的退出码。 |
| `已终止` | Spinney 或你终止了进程树。 |
| `已结束` | 记录的终点。 |

分离任务从不显示 `待投递`，因为它不发送通知。

后台任务属于启动它的节点。它不会锁定另一个分支或另一个会话。`#id` 是会话计数器，不是操作系统的 pid。

任务结束时，Spinney 用与投递子智能体通知相同的方式投递一条通知。之后卡片保留为记录，带有一个 `Delivered` 徽标。

Spinney 在以下情况下终止正在运行的任务：

- 你在拥有该任务的节点上按 **停止**。
- 你删除该分支或该会话，或者清空对话。会先弹出一个模态框询问。
- 你关闭窗口。

重启后，正在运行的任务显示为 `已中断`。卡片绝不会在并非活动时声称自己是活动的。

子智能体可以启动后台终端，但不能管理它。只有你能终止它。

## 9. 图片

用 **附加图片** 按钮附加图片，或把图片粘贴到输入框。待处理的附件显示为小图片，带一个 **×** 按钮。

只有 `vision.enabled` 的卡片接受图片。Spinney 自带的 `deepseek-flash` 已开启图片支持。

| 情况 | 会发生什么 |
|---|---|
| 卡片不支持图片 | 附件被拒绝：`切换到支持图像的模型（{0}）即可附加图片。` |
| 没有卡片支持图片 | `没有配置支持图像的模型 — 请在某张模型卡片上启用视觉支持以附加图片。` |
| 你切换到不支持图片的卡片 | Spinney 隐藏历史中的图片。它保留数据，并在支持图片的卡片回来时恢复数据。 |
| 传输方式为 `deepseek` | Spinney 先上传图片。状态行随后显示 `正在上传图片…`。**停止** 会中止那次发送。 |
| 上传失败 | `无法上传：{0}。这些图片已被省略。` |

一张图片最大 64 MiB。格式为 JPEG、PNG、GIF 和 WebP。Spinney 从内容读取格式，而不是从文件名。

已上传的图片不能移到另一个服务商。`file_id` 只属于生成它的服务商。卡片显示 `[image hidden: it was uploaded to a provider that this model cannot read from]`。`openai` 传输没有这个问题。

## 10. 错误、重试与继续

### 10.1 自动重试

Spinney 最多重试一个请求 10 次。等待时间为 1 秒、2 秒、4 秒，依此类推，上限为 30 秒。

状态行显示 `模型调用失败（{0}/{1}）；{2} 后重试…`。第一个数字是失败的尝试次数。

Spinney 重试这些失败：

- 网络错误。
- HTTP `408`、`429` 或任何 `5xx`。
- 一个 `200` 应答，但正文为空。

Spinney 不重试这些失败：

- HTTP `400`、`401`、`403`、`404` 或 `422`。这些无法自行修复。
- 流中间的断点。重试会重复输出。
- 图片上传。
- 余额读取。

等待期间按 **停止** 会立即结束重试。

停滞的请求有边界。Spinney 为首字节等待 20 秒，为首块等待 20 秒，块之间等待 60 秒。停滞的请求显示 `思考中…`，且 `tok/s` 为 0。

### 10.2 卡片按钮

已结束的卡片可以带三个按钮之一，也可以同时带两个。按钮取决于节点的状态。

| 节点状态 | 按钮 | 作用 |
|---|---|---|
| `已中断` | **▶ 继续** | 发送一条 harness 消息，并在同一张卡片中恢复该回合。部分输出保留。 |
| `错误` | **↻ 重试** | 发送一条 harness 消息，并从该节点重新运行该回合。失败回合的部分输出被丢弃。 |
| `错误`，上下文达到 90% 或以上但未满 | **↻ 重试** 和 **⧉ 在新窗口中继续** | 两个按钮。重试在本窗口中重新运行该回合。另一个提供新窗口。它的工具提示显示百分比。见第 10.3 节。 |
| `已中断`，上下文达到 90% 或以上 | **⧉ 在新窗口中继续** | 提供一个新上下文窗口。工具提示显示百分比。见第 10.3 节。 |
| `错误`，上下文已满 | **⧉ 在新窗口中继续** | 启动一个新的上下文窗口。上下文窗口可能因 token 已满，也可能因图片字节已满。见第 10.3 节。 |

按钮承担这项工作。你不需要自己输入指令。

### 10.3 上下文窗口已满

当服务商用上下文长度错误应答时，上下文窗口就满了。请求还会携带其中的图片，形式是已上传的字节。服务商把这些字节的上限设为每个请求 200 MB。因为这个原因被拒绝，也算窗口已满。例如，消息为 `Total image size exceeds the limit: max 200 MB per request, got 203 MB`。Spinney 不会从 `ctx` 读数猜测限制。卡片显示一条 **⚠️** 消息，按钮变为 **⧉ 在新窗口中继续**。

在失败之前，Spinney 也会提供这个按钮。回合结束但没有回答的卡片，在卡片的 `contextWindow` 用到约 90% 时就会提供它。工具提示带有这个数字，例如 `Context 93% full - continue in a new window`。这是一个建议，不是修复。没有任何东西失败时，按钮单独出现。在 90% 或以上失败的卡片会把它显示在 **↻ 重试** 旁边：服务商没有拒绝任何内容，因此两个动作都保留。

两种情况下，Spinney 都会问新节点必须以哪个配置开始（第 3.4 节）：

- `Continue with current setup`。新节点沿用其上方对话的配置。
- `Continue with latest setup`。新节点冻结最新配置。

这里两种回答都不付出代价。新的上下文窗口从空开始，因此没有可丢失的缓存前缀。

1. 点击 **⧉ 在新窗口中继续**。如果该节点仍拥有正在运行的工作，会先弹出一个模态框询问。它列出将停止的工作。
2. Spinney 在该节点下方打开一张新卡片。边为虚线，标题为 `上下文窗口 {0}`，徽标为 `CTX`。

新窗口以系统提示词和一条 harness 消息开始。该消息以缩短的形式保存你的最后一次请求和最后一次回答。其他内容都不会发给模型。附件无法跨越，因此该消息改为列出它们的名称。

旧分支仍然可用。你可以再次向它发送，或在那里按 **▶ 继续**，直到它再次溢出。

`CTX` 的工具提示为 `此节点开启新的上下文窗口；其上方分支不再发送给模型`。

两个不是故障的细节：

- 新卡片不带固定的用户消息。harness 开启的回合没有这种消息。
- 无论显示语言是什么，harness 的文本都是英文。

所有键都以 `spinney.` 开头。打开设置 UI，或编辑 `settings.json`。

| `spinney.subAgentTranscriptDir` | `""` | 转写文件的文件夹，相对于智能体根目录。为空表示扩展存储。 |
| `spinney.dataDir` | `""` | 存放会话的文件夹。为空表示扩展存储下的固定文件夹，且不以扩展 id 命名——重命名或重装都不会移动你的历史。填入你备份的文件夹即可把历史放在本机 profile 之外。下次重载窗口后生效。 |
| `spinney.diagnostics.log` | `true` | 为本窗口写诊断日志。其中只有耗时、计数与路径——不含你的对话。每一行都以时间戳结尾。命令开始时还会写一行，运行期间每 30 秒写一行心跳，结束时写一行。每个窗口一个文件，更旧的文件被删除，单个文件到 2 MiB 时轮转。 |
| `spinney.httpApi.enabled` | `false` | 打开本地 HTTP 控制平面。见第 14 节。 |
| `spinney.httpApi.port` | `0` | 该控制平面的端口。`0` 让系统选一个。 |

变更立即生效，只有一个例外：`AGENTS.md` 需要重新加载窗口（第 13 节）。

| `Spinney: 导入会话数据` | 把你选择的文件夹中的会话并入当前窗口。 |
| `Spinney: 打开诊断日志` | 显示本窗口的诊断日志，并提供在资源管理器中定位。 |
| `Spinney: 删除检出回合处的分支` | 删除检出回合处的分支。 |
| `Spinney: 清除对话` | 清空当前会话的对话。 |
| `Spinney: 打开模型卡片` | 打开模型卡片页面。 |
| `Spinney: 设置 API 密钥` | 为某个服务商保存 API 密钥。 |

## 13. 工作区指令

Spinney 读取工作区根目录中的 `AGENTS.md`，并把它加入系统提示词。用它写你项目的规则，例如测试命令或代码风格。

两个要知道的事实：

- Spinney 在扩展宿主启动时读取该文件一次。编辑不会到达正在运行的窗口。更改文件后请重新加载窗口。
- 未打开文件夹时，Spinney 不读取任何内容。

运行 **`Spinney: 显示系统提示词`** 可读取模型收到的准确提示词。内容跟随当前模型卡片、推理力度、回复语言，以及该会话的 `AGENTS.md` 快照。

## 14. 隐私与数据

Spinney 不发送遥测。它只连接你配置的服务商端点。

一个请求携带你的消息、工具结果和图片。余额读取会向服务商增加一个请求。图片根据卡片的传输方式，以上传方式或请求体内联方式发往服务商。

扩展不保存已上传图片字节的任何副本。

| 内容 | 位置 |
|---|---|
| 对话 | VS Code 状态数据库，不是文件。工作区一行，或未打开文件夹时配置档案一行。 |
| 转写 | JSONL 文件，每个已结束的回合一个，每个子智能体一个。文件夹：扩展存储，或 `spinney.subAgentTranscriptDir`。 |
| 大的工具结果 | `<agent root>/.spinney/tool-output/`。 |
| API 密钥 | VS Code 密钥存储，由操作系统加密。绝不在 `settings.json` 中。 |
| 设置 | `settings.json`。模型卡片页面写在 **Global** 作用域。 |

Spinney 不会向你的 `.gitignore` 写入任何内容。如果你不想让溢出的工具输出进入提交，请自己添加 `.spinney/` 文件夹。

卸载后对话仍留在状态数据库中。第 15 节会移除它们。

### 14.1 HTTP 控制平面

控制平面默认关闭。它监听 `127.0.0.1`，并需要一个 bearer token。

它为外部控制程序而存在。`POST /continue` 让智能体运行一条来自调用方的指令。把这个端口当作你机器的信任边界。只有在你需要时才打开它。

控制平面打开时，Spinney 把端口和 token 写入 `<extension storage>/http/<instanceId>.json`。

## 15. 卸载与清除数据

1. 为每个服务商运行 **`Spinney: 清除 API 密钥`**，或接受密钥仍然保留。
2. 在扩展视图中卸载 Spinney。
3. 手动删除文件夹 `<extension storage>/de-yu.spinney`。它保存转写、备份和控制平面文件。
4. 同时删除对话行。在状态数据库中，键为 `DE-YU.spinney`。一行位于 `globalStorage/state.vscdb`，另外每个 `<workspaceStorage>/<hash>/state.vscdb` 中各有一行。

注意两种拼写：文件夹名是小写，而行键保留扩展 id 的大小写。

你指定到自己文件夹的文件不在这些步骤之内。检查 `spinney.subAgentTranscriptDir` 和任何 `.spinney/` 文件夹。

## 16. 无文件夹模式

Spinney 在未打开任何文件夹的窗口中也能工作。

- 工具调用中的相对路径以扩展存储中的暂存文件夹 `<extension storage>/no-workspace` 为基准解析。智能体通过绝对路径访问你的真实文件。
- 会话位于配置档案中，而不是工作区中。该配置档案的每个无文件夹窗口都显示相同的会话。一次只用一个窗口。
- Spinney 不读取 `AGENTS.md`，因为没有工作区根目录。
- 溢出的工具结果发往 `<scratch folder>/.spinney/tool-output/`。

在同一窗口中打开一个文件夹，或关闭一个文件夹，Spinney 会立即切换模式。

## 17. 故障排除

| 症状 | 原因与修复 |
|---|---|
| `No API key configured for this provider.` | 用 `Spinney: 设置 API 密钥` 设置密钥，或在模型卡片页面为具名服务商设置。 |
| 请求立即失败，没有重试 | `400`、`401`、`403`、`404` 或 `422`。阅读消息。常见原因是密钥错误和模型名称错误。 |
| 状态行重复 `retrying` | 网络故障、`429` 或 `5xx`。状态行无法区分死套接字和服务商错误。按 **停止** 结束等待。 |
| `思考中…` 且 `tok/s` 长时间为 0 | 流停滞。看门狗在 20 秒到 60 秒后结束它。 |
| `ctx N%` 看起来不对 | 它用**上一次**请求的提示 token 除以卡片的 `contextWindow`。检查卡片的值。 |
| 没有余额数字 | 服务商的 `balance` 值为 `none`，或读取失败。Spinney 只读取一次余额，且从不重试。 |
| 智能体忽略 `AGENTS.md` 中的新规则 | 重新加载窗口。Spinney 每次激活只读取该文件一次。 |
| 图片无法附加 | 当前卡片不支持图片。为卡片添加 `vision`，或切换到支持图片的卡片。 |
| 回合开始前要等待 | 并发闸门。状态行会说明等待原因。提高服务商或卡片上的 `concurrency`，或者等待。 |
| 模型下拉列表是灰色 | 本会话中有回合在运行。停止它或等待它。 |
| 视图停在旧卡片上 | 手动平移或缩放关闭了跟随模式。点击 **跟随活动节点**。 |

**Spinney** 输出通道保存诊断信息。用 View → Output 打开它，然后在列表中选择 `Spinney`。它会说明显示语言、模型配置问题，以及布局和性能行。

运行 **`Spinney: 显示系统提示词`** 查看准确提示词，运行 **`Spinney: 显示用户手册`** 重新打开本手册。


## 18. 上报卡顿或异常

Spinney 为每个窗口保留一份诊断日志。其中只有耗时、计数与路径——不含你输入的内容，也不含 API 密钥。

日志的每一行都以时间戳结尾，例如 ` | at=2026-09-21T04:14:48.123Z`。日志还会在命令开始时写一行、命令运行期间每 30 秒写一行心跳，并在命令结束时写一行。因此，卡住的命令事后能在日志中看到。日志也会记录后台任务的预算：Spinney 登记该任务时写一行（`bg register … budget=…`），预算用尽时再写一行（`bg expire …`）。

| 步骤 | 做法 |
|---|---|
| 1 | 复现问题。 |
| 2 | 运行 `Spinney: 打开诊断日志`，然后点 **在资源管理器中显示**。 |
| 3 | 把那一份文件发给支持你的人。 |

从输出面板复制的文字不是同一份文件：它没有文件头那一行，而该行会写明构建、进程与窗口的启动时间。

把 `spinney.diagnostics.log` 设为 `false` 可以停掉它。

Spinney 没有启动的进程可能残留。当一条命令把工作交给另一个程序时就会发生这种情况，例如编辑器、构建服务器或测试桥接程序。该程序的子进程在 Spinney 的进程树之外。**停止** 无法触及它，它的输出也永远回不来。Spinney 无法替你找到这样的进程。请使用任务管理器，或在 PowerShell 中运行以下命令：

```powershell
Get-CimInstance Win32_Process -Filter "name like '<program>%'" | Where-Object { $_.CreationDate -lt (Get-Date).AddHours(-2) } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

把 `<program>` 替换为残留程序的名称。该筛选条件匹配启动超过两小时的进程。

## 19. 网络搜索

Agent 可以搜索网络，并读取一个页面。这两个工具都不需要 API 密钥，也不需要任何设置。

| 工具 | 作用 |
|---|---|
| `web_search` | 把查询发给一组搜索后端，返回编号的结果列表：标题、网址和摘要。 |
| `web_fetch` | 读取一个网址，返回该页面的文本。HTML 页面会转换成 Markdown。 |

搜索后端是内置的。Spinney 按此顺序尝试：Bing (RSS)、360、百度、搜狗、Bing (HTML)、Hacker News、StackExchange、GitHub。结果里写明由哪个后端作答，以及其余后端各自的结果。

两条规则让搜索保持可用：

- 后端返回验证码或验证页面时，Spinney 会标记该后端，并在一段时间内跳过它；重复失败后跳过的更久。
- 网络不同，可用的后端也不同。部分地域无法访问 DuckDuckGo、Google、Mojeek 和 Wikipedia；另一些地域访问百度、搜狗和 360 时会遇到验证码。

搜索没有结果时，运行 **`Spinney: 测试网络搜索后端`**。Spinney 会向每个后端发送一个测试查询，并打开一张表，列出各自的结果、耗时和命中数。该命令只做测量，不修改任何设置。

`web_fetch` 会跟随一次跳转，最多读取 2 MB，并使用页面自身的字符集。它不执行 JavaScript。由浏览器动态生成的页面只会返回很少的文本，结果中会说明这一点。`web_fetch` 会拒绝私有地址，例如 `localhost` 和 `127.0.0.1`。

页面的文本不是对 Spinney 的命令。Spinney 把它视为陌生人的信息。如果页面试图对 Spinney 下达指令，Spinney 会向你报告。
